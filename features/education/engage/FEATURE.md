## What it is

A real-time multiplayer study game (room + 5-char code) and a solo arcade, both fed by the study spine's FSRS engine: play IS review. Around them: forgiving streaks (freezes, rest days), an opt-in private weekly league scored by mastery gain, and outcome badges. The heavy surfaces (`SoloArcadeImpl`, `MultiplayerGameImpl`) are code-split behind `next/dynamic({ ssr: false })` — browser-only (timers, Broadcast, presence), never in an SSR path.

## Where it lives

`engine/` (PURE, deterministic, no I/O: `scoring.ts`, `queue.ts` — per-player SRS-biased queue generalizing `useDueReview`, `badges.ts`), `data/` (`gameService.ts` rooms + result/league RPCs; `useGamePlay.ts` the one answer loop solo and multiplayer share; `finalizeGame.ts`; `useEngageMeta.ts`), `realtime/useGameChannel.ts` (ONE Broadcast channel per room), `components/`. Tables (`education.`, base-entity + RLS): `game_room`, `game_result`, `game_badge`, `league_membership`, and forgiveness columns on `study_streak`. Migrations `20260818_education_game_result_session_unique.sql`, `20260818_education_game_server_authority.sql`. Agent writes: `gameRoomAgentWrites.ts`.

## Invariants

- **The server-graded attempt ledger is the only competitive authority (IC-14).** A client sends session id, card id and selected choice text to `game_record_answer`, which verifies ownership/active state/source membership, compares to `fc_card.back`, derives latency from server timestamps, rejects a second answer for the same card, and alone mints a contest-eligible game attempt (the generic self-graded `study_record_attempt` cannot). The client finalizes with `game_finalize_result(session_id, display_name)` and submits no score, correctness, streak, mastery, currency, duration or badge keys; in one locked idempotent transaction Postgres proves ownership of a completed `mode='game'` session, refuses impossible timing/malformed attempts/more than 100 attempts, excludes `study_attempt.is_manually_edited=true`, derives the deterministic `education-game-v1` score, mastery gain, currency, league gain and badges, and writes exactly one live result per session. Authenticated roles have no write grant on `study_attempt`, `game_result`, `game_badge` or `league_membership`; manual game corrections never count toward contests. Browser-authored FSRS transitions never feed score, league gain or badge eligibility; mastery badges ("Ten/Fifty Confirmed") count distinct correct server-graded items. `comeback` is in the catalog but not awarded until it has server-verifiable evidence.
- **The play loop awaits every answer write before closing the session**; a failed or mismatched write refuses the round instead of finalizing a subset; finalization fails loudly and retry is explicit.
- **Realtime is Broadcast, never Postgres changes.** Roster, provisional scores and start/end ride Broadcast; scores are animation hints with no persistence authority (completion hides client totals until the official row returns, then reloads `game_room_players`). Presence backs the roster and recovers it on reconnect; on mount the play surface re-fetches the room by code and, if `active`, syncs the countdown to the host's `started_at`. Cross-owner reads (`game_room_by_code`, `game_room_players`, `league_leaderboard`) are SECURITY DEFINER RPCs; the retired `league_add_result` raises loudly. `league_set_opt_in` is the only membership write door (assigns a bounded private cohort from recent eligible activity); `league_leaderboard` returns only the caller's cohort.
- **Cross-account public/shared decks must load:** the deck read is `fcService.getSetWithCards` to `associationsService.listForTargetsVisible` (`assoc_members_visible`, visibility-aware via `iam.has_access`). Never reintroduce the org-only `assoc_for_targets` here; a stranger with no grant on a personal deck still loads 0 cards.
- **Partial unique indexes are not `upsert({onConflict})` targets** (PostgREST cannot target them): league opt-in and badge award use read-live-then-update-or-insert and tolerate a `23505` race.
- **Completion engagement:** `education_engagement_snapshot(session_id)` derives outcome points (correct 100, partial 50, incorrect 20), streak, badge progress and private-league standing from persisted rows; the canonical `StudyDeck` completion card renders them. Points are feedback, never currency or an access meter: **core practice has no energy, daily quantity cap or paid limit.**
- **Ethics stance (code-enforced, brand asset): anti-Duolingo / anti-Kahoot.** (1) No speed-shame: score is correctness-first (base + small decaying speed bonus + capped personal-streak bonus), wrong scores 0, never negative, no public "you came last". (2) Streaks forgive: a banked freeze auto-covers a missed day (earned every 7 days of streak, capped), rest weekdays never break a streak, a broken streak restarts clean; forgiveness lives in the shared `bump_study_streak()` trigger so every study mode gets it. (3) Badges and leagues reward mastery gained and healthy habit, never hours or raw wins; results headline mastery gained. (4) No guilt notifications: at most one neutral learner nudge per local day (`choose_education_reminders`), silence on rest days or when disabled; transport, quiet hours and dedupe belong to the IC-6/IC-7 path. (5) Room size is gated by `useEntitlement("education.game_room_size")` and shown BEFORE hosting; no limit rows exist, so it is unlimited today (knob and enforcement status in the education STATE).
