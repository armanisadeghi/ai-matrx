## Purpose

The AI study platform surface. `/education` is the desktop-first, mobile-responsive marketing and discovery landing; `/education/overview` is the compact signed-in navigation hub; `/education/library` is the canonical scoped list of the learner's persisted study artifacts.

## Why `(core)`, not `(public)` — load-bearing

The hub lives in `app/(core)/education/`, not `(public)`. `(core)` does **not** auth-gate: `(core)/layout.tsx` builds a guest user and `utils/supabase/middleware.ts` lists only `/administration`, `/api/admin`, `/dashboard`, `/scraper` as `requiresAuth`. So **every `/education/*` page is publicly crawlable** AND inherits the app shell + the `AuthedWorkspaceCTA` sign-up banner + authed continuity. Trade-off: the `(core)` layout reads `headers()`, forcing **dynamic rendering** (no static/ISR). That is fine for SEO (crawlers get full server HTML). For high-traffic content, opt into caching with **`'use cache'` + `cacheTag()`** — never relocate to `(public)` (you'd lose the shell + CTA).

## Two layers, one rule each

- **Marketing / discovery + content (server-only).** The five axes and the `/learn` content engine. **100% server-rendered, zero client logic** — pure SSR for SEO and speed. Page body JSX lives in exactly one place: `SectionRenderer`.
- **Application tools (interactive).** `/education/<tool>` — **16** tools registered in `tools.ts`, all carrying `status: "live"` (flashcards, fastfire, tutor, quizzes, practice-tests, audio-study, mind-maps, memory, notes, planner, practice-oral, grade-work, game, family, classes, creator). 🚨 **`status: "live"` here means "a working desktop happy path exists that writes to the database" — it is NOT a statement about mobile parity, depth, or quality**, and reading it as one is what produced the 2026-07 "system is complete" claim. Per-tool truth values are tracked as claim C-13 in the education program's `CLAIM_REGISTER.md`. The hub's **"Study tools" section** (`EducationHub.tsx` → `buildStudyToolCards()`, live+featured-first, same sort idiom as `AxisIndex.tsx`) is the front door — data-driven off `EDU_TOOLS`, so a newly-shipped tool surfaces there automatically the moment its entry flips to `live`; never hand-add it to a second list. Each built tool graduates from `EduComingSoon` to a real surface at the same slug (server shell, code-split client island) — the placeholder mechanism stays live for the next unbuilt tool. **FastFire** (`/education/fastfire`) is the voice-graded flashcard drill — see [`features/flashcards/fast-fire/`](../flashcards/fast-fire/) (ONE state-machine slice `fastFireSlice`, continuous mic capture, deadline-timer-driven advance, fire-and-forget agent grading on the shared study spine). Its grader / live-help / batch-review lanes resolve through **mandates** (`flashcards.grade_spoken` / `flashcards.help_live` / `flashcards.review_batch`, keys in `features/flashcards/data/mandates.ts`; swap agents at `/agents/mandates` — the old localStorage config is retired); the drill still runs + records a result-less attempt when no audio was captured.

**Content vs app separation** mirrors the industry (Quizlet `/explanations`, Course Hero `/sg`): content pages are keyword-rich, server-rendered, and link **into** the tools (the conversion bridge via each entry's `related.tools`). Tool routes are short, ID-anchored.

## Invariants & gotchas

- **Routing contract → [`app/(core)/education/ROUTING.md`](<../../app/(core)/education/ROUTING.md>). Read it before adding any route.** Marketing/content is **nested + data-driven** (`education/<axis>/[slug]`, `education/learn/[...slug]`); app tools are **FLAT** (`education/<tool>` + sub-routes) — never nest a tool under an axis, never scatter it into `(transitional)`/`(legacy)`/a sibling feature. A tool graduates from its coming-soon placeholder to the real build **at the same slug**.
- **View/edit split (the share-gating fundamental).** Per tool: `[id]` (+ use-modes like `study`/`take`/`results`) is gated by **VIEW** access (the shareable URL); `[id]/edit` is a separate segment gated by **EDIT** permission (view-only sharees redirect to `[id]`). Gate via `iam.has_access` + the permissions registry, not a bespoke check. Models Google Docs / Quizlet.
- **Marketing/content pages never `"use client"`.** Interactivity goes in leaf client components (e.g. `AuthedWorkspaceCTA`), never the page.
- **Agent-generated study content renders through the KIND-AWARE engine, not `BasicMarkdownContent`.** Any surface that displays free-form agent output which may carry a `__kind` block (fenced JSON / XML — `flashcard_set`, `diagram_spec`, tables, mermaid, …) renders it via `MarkdownStream` (`@/components/MarkdownStream` — the code-split, `ssr:false` rich-document engine), so the shapes become interactive components instead of raw JSON/markdown. Reference: `onboard/SummaryDetail.tsx`. `BasicMarkdownContent` stays ONLY for genuinely plain, shape-free strings (short labels, single-line explanations). Structured education artifacts render through their REGISTERED kind's canonical component (`MemoryAidBlock`/`MemoryHintBlock` for `memory_aid`/`memory_hint`, `MindMapView` via `InteractiveDiagramBlock` for `diagram_spec`) — never a hand-rolled viewer for a registered kind; quiz/assessment components render persisted `assessment_item` rows (a gray area awaiting Arman's ruling, see `docs/handoffs/canonical-component-sweep.md`). `study_summary` is still an UNREGISTERED `__kind` with a hand-written renderer — registering it is the tracked fix in that same handoff.
- **`SectionRenderer` is the only home for page-body markup.** New block type → extend the `EduSection` union + add one branch. Never inline bespoke JSX in a registry entry.
- **Registry icons must resolve at lucide-react RUNTIME, not just type-level.** Lucide dropped its brand icons (e.g. `Youtube`) — a type-valid-but-runtime-missing icon compiles, passes `tsc`, then **500s every education route** through the shared `registry.ts`. Validate new icons at runtime (`node -e "console.log('Video' in require('lucide-react'))"`), never `tsc` alone.
- **`quick-` prefix = stock/preview content in a non-permanent slot.** `subjects/quick-math` (static route) holds the relocated stock algebra lessons and coexists with the dynamic `subjects/[slug]` (static wins). `subjects/math` **is** a marketing subject entry like every subject; the full interactive math _experience_ is a future tool build linked from it — the headroom the `quick-` split reserves. (Open question for the user: should `/subjects/math` instead be reserved as the interactive experience itself? Flagged at demo.)
- 🚨 **THERE IS NO PAYWALL, SO NOTHING MAY CLAIM ONE.** The free/trial/premium `AccessTierBadge` was **deleted 2026-08-19**: it rendered on flashcards, tutor, practice-tests, audio, planner, spoken-practice and grade-work while not one code path gated on it and all 16 `education.*` rows in `billing.capability` were `enforced: false`. Program law D-6 — _a claim we cannot support is deleted, not deferred_ — and a trial/premium badge is a claim. **The `accessTier` field survives on `AxisEntry` / `EduToolEntry` (registry data only) as input for entitlements; `EduStatusCard` no longer carries it and no renderer, agent scope, or API payload may surface it.** The badge — and any other tier label, "Pro" chip, or upgrade prompt — **returns only when a gate actually reads a tier**, i.e. when the education capabilities are `enforced: true` behind decided free-tier numbers (owner decision, [`STATE.md`](../../../common-docs/systems/education/STATE.md) Q2). Do **not** flip enforcement on to make a badge true; that is the wrong direction. Enforcement is owned by `features/entitlements` — see [`STATE.md`](../../../common-docs/systems/education/STATE.md) §4.1 E.
- **Taxonomy is evidence-backed** (Khan/IXL/Quizlet/Course Hero, June 2026): subject-first; Levels is a three-band model (per-grade K–5 → bands → professional); Exam Prep is its own flat cross-cutting axis. Don't restructure without re-checking the research + the user.

- **A learner declining microphone permission is expected input, not a crash.** Voice-test surfaces show the browser-settings repair path inline and must not send `NotAllowedError` / `PermissionDeniedError` through `console.error`; unexpected mic failures stay loud.

It now survives.
  - 🚨 **THE DECISION: HOLD THE ATTEMPT BACK, don't record-then-attach.** The alternative was `study_override_attempt`, and reading it settles the question rather than leaving it a matter of taste. That RPC sets `is_manually_edited = true` and `edited_by = auth.uid()` — it would brand an **AI** grade as the **LEARNER'S own manual correction**, on the exact flag the migration's own comment reserves for future contest/leaderboard integrity. It also cannot write `response_audio_file_id`, `response_transcript` or `graded_by` at all, so the audio would _still_ be detached, and it replays the item's entire attempt history on every call. `study_record_attempt` is idempotent BY ID and touches nothing on replay, so there is no third option. A spoken attempt whose clip did not upload is therefore **queued but never written to the ledger** until the flush can upload and grade it, then written **ONCE, complete** — grade, transcript, mandate and durable audio pointer together.
  - **The founding rule is intact.** The outbox still stores only what the learner DID — what they said (the bytes) and what they were asked (front/back/seconds/mandate key). No grade is ever queued, and **no attempt ever carries a grade the server did not produce**; that negative assertion is the one the test suite protects hardest.
  - **The architectural expansion is one function type.** Grading needs `fileHandler.upload` and a headless agent run, which need `dispatch`/`getState` — dragging those into `replay.ts` would end its life as a pure service module. Instead the loop declares a `PendingGradeResolver` type and the one caller that already owns a store (`useOfflineStudySync`) builds it in the new `study/offline/resolvePendingGrade.ts` and injects it. No registry, no singleton, no service layer. **The resolver reuses `uploadResponseClip` + `runSpokenGrader`** — a held answer is graded by literally the code that would have graded it live. With no resolver injected, a held attempt records as the bare observation rather than blocking the queue behind a capability that caller lacks.
  - **Ordering was free.** Resolution happens INSIDE the sequential loop, so a slow re-grade delays the attempts behind it and can never let one overtake another — the property FSRS depends on. A test drives it with a deliberately slow first upload.
  - **Bounded, both ways.** A transient failure keeps the answer held and halts the flush (ordering); after `MAX_GRADE_RETRIES` (5, higher than the ledger's 3 because these failures are mostly a flaky first minute back on signal) the attempt records ungraded — an answer held forever would stop the learner's **work** counting too. And when the upload succeeds but the grader fails, the attempt records **with its audio and no grade**: an ungraded attempt WITH audio can be graded later by anything that can see it, one without audio never can.
  - **Storage is bytes, not Blobs, and the budget REFUSES rather than evicts.** Clips live in their own Dexie table (v2, with v1 declared verbatim so an existing queue upgrades instead of being torn down) keyed by `attemptId` — on the attempt row, `listPendingAttempts` would pull every megabyte into memory on every queue-depth poll. They are stored as `ArrayBuffer` + mime type because structured clone handles Blobs inconsistently (Safari shipped years of IndexedDB builds returning an empty object, and `fake-indexeddb` does it today — the bug would have been invisible in tests and silent in the field), and read via `Blob.arrayBuffer()` with a `FileReader` fallback for older iOS. **Budget: 25 MB per clip, 250 MB per learner** — an agent decision under blind approval, basis and 2026-10-20 review date recorded in `outbox.ts`; deliberately NOT an admin knob, because the bytes are on the learner's own disk, cost us nothing, and routing the number through a server fetch would make offline capture depend on the network. When the budget is full the NEW clip is refused, never an old one evicted: every held clip belongs to an answer we already told the learner was saved. Every refusal is its own toast naming the actual reason.

The no-recording case keeps the honest ungraded wording, and the flush reports graded/ungraded counts back to the learner on reconnect.
