# Assists — AI assists everywhere (frontend half)

Cross-repo system-of-record: `/Users/armanisadeghi/code/common-docs/systems/platform/assists/FEATURE.md` — read it before touching this feature in ANY repo. This doc covers only this repo's wiring.

Chip Rescue rubric, producer dispositions, live controls, and migration state:
`/Users/armanisadeghi/code/common-docs/projects/chip-rescue/HANDOFF.md`.

**What it is:** the platform-wide one-click-AI-help primitive. Deterministic code, background agents, sweeps, and stream events notice things and produce **assists**; the user sees chips; accepting one dispatches the typed `action` binding through ONE registry. The standing design gate: every friction point gets asked _"could an AI button/chip do this for the user?"_ BEFORE a manual affordance is designed.

**Two layers, page first (Arman's ruling, 2026-08-08):** the PAGE layer is the original vision — chips that react to what's on THIS page, mounted with one line (`<AssistStrip surfaceName="…" />`); the AMBIENT layer (the global dock) carries background/server-noticed items. **Every agent building a page asks: which assists does this page need?** The dock is the overflow, never the substitute for in-place chips.

## 🚨 THE INTENTIONAL-ACTION LAW (Arman, 2026-08-08, after being burned)

A chip NEVER runs from an ambiguous gesture. Hover expands the FULL card immediately (complete title, readable markdown, scrolls when long — Claude Code is the bar); clicking the chip expands, never runs; execution is a **verb-labeled button** whose one-line explainer says exactly what will happen BEFORE it happens, and a **receipt toast** says what happened after. Truncated text with no instant full reveal is banned everywhere in this feature. Every new action kind MUST add a descriptor in `runtime/action-descriptors.ts` — a kind without one renders a disabled action, never a mystery button.

## 🚨 THE USER OWNS THE CORNER (Arman, 2026-08-19)

Fifty chips accumulated in a dock that could be neither moved nor closed, and the reaction was the one that kills the feature: _"the more they become, the less likely I am to engage."_ Three properties are now non-negotiable, and each has to be REAL:

- **Movable.** The dock drags anywhere on desktop (`useDockDrag` + `dock-position.ts`), per-user and synced. A drag is never a click; the offset is re-clamped to the viewport on every render, so a position saved on a big monitor can't park it off-screen on a laptop.
- **Closable.** A hover-revealed X on the dock and one on every chip. The chip's X dismisses that assist; the dock's X quiets everything for the rest of the day, with Undo on the toast.
- **Mobile is an inbox, not a draggable desktop chip.** Phones render one 44pt icon button at the bottom edge with a count badge; tapping opens the canonical chips in a swipe-dismissable 85dvh Drawer with an explicit **Quiet for 24 hours** action. The launcher moves below the visual viewport while the software keyboard is open, so it never hovers over a composer or typed text. Mobile never depends on dragging or hover-only controls.
- **QUIET STOPS PRODUCTION, NOT JUST PIXELS.** This is the whole point: _"we're spending money to come up with suggestions that they're not even looking at."_ A mute that only hides chips keeps paying for them. `emitAssistTracked` — the one door every client producer comes through — returns null while quiet, so no row is written and no agent is launched to think one up.

**Never add a mute that only affects rendering.** If a new surface can hide an assist, it goes through the quiet vocabulary or it is a defect.

## Quiet — one vocabulary, three scopes

`quiet.ts` owns the windows (1 hour · 4 hours · Rest of today · Tomorrow · A week · Until I turn it back on) and the one meaning of the stored value: `null` = not quiet, `"infinity"` = until reversed, anything else an ISO timestamp that simply passes.

| Scope          | Stored in                                           | Set from                                 |
| -------------- | --------------------------------------------------- | ---------------------------------------- |
| **Everything** | `preferences.assists.quietUntil` (synced prefs)     | the dock's X and its clock menu          |
| **One kind**   | `platform.assists.suppressed_until` across a source | the card's "Stop showing" menu           |
| **One assist** | the same column on one row (an ordinary snooze)     | the card's "Later" menu (`constants.ts`) |

Two rules that are easy to get wrong:

- **A timed source quiet is NOT distinguished by its timestamp** — a finite `suppressed_until` is also what a per-assist snooze writes. What separates them is the `metadata.source_suppression` record, which only a source-level mute writes. Every read that means "which kinds are quiet" filters on that key.
- **The insert trigger inherits the WINDOW, not just `infinity`** (`private.inherit_assist_source_suppression`, migration `platform_assists_timed_source_quiet.sql`). Before that generalization, "quiet this kind for four hours" was punched straight through by the producer's next dedupe key — a mute that lasts until the next cron tick is worse than no mute, because the user believes it worked.
- **A reason is required only for the permanent form.** A window reverses itself and needs no record for the future to interpret; demanding an essay in front of "quiet for an hour" is how a control stops being used.

## Urgency is a BAND over `priority`, never a new column

`platform.assists.priority` (smallint, indexed, already the queue's sort key) has always carried urgency implicitly — producers write 0 for "here is something you could do", 10 for recovery/attention, 20 for something a human must decide. Those bands are now named, in ONE place: `urgencyFromPriority()` + `ASSIST_URGENCY_MIN_PRIORITY` + `ASSIST_URGENCY_META` in `types.ts`.

| Band       | `priority` | Chip / card                            | Means                  |
| ---------- | ---------- | -------------------------------------- | ---------------------- |
| `normal`   | `< 10`     | primary lightbulb, unchanged           | Something you could do |
| `elevated` | `10–19`    | amber, triangle icon, "Elevated" badge | Worth looking at soon  |
| `urgent`   | `>= 20`    | red, octagon icon, "Urgent" badge      | Waiting on you         |

🚨 **THE URGENT BAR — what earns red, platform-wide: _something is blocked or failing and only this user can unblock it._** A workflow paused on a human decision is urgent. A capture pipeline dropping data is urgent. A backlog is NOT, however severe in its own domain — a queue that shouts every day is a queue nobody reads.

🚨 **Producers build the number with `assistPriority(band, rank)` — never by hand.** `rank` is a clamped 0-9 ordering signal _inside_ the band, so worst-first survives and no producer can spill into the band above. Guard: **`pnpm check:assist-priority`** (loud, advisory) fails any bare `priority: <n>` in a producer.

> **Why the helper is mandatory — the 2026-08-15 incident.** This column was indexed and sorted on for months with no _rendered_ meaning, so producers split into two scales that nobody could see at once: an urgency band (every aidream producer — 2 / 10 / 20 / 40) and a raw 0-100 domain severity score (competitor-confirm at 80, the finding sweep at `severity_rank × 10 + scope`, backlinks at 15-40). Both were locally sensible. The hour the bands started rendering, **35 of 96 live chips turned red** — led by "Confirm indeed.com" sitting above workflows genuinely blocked on a human. Remapped to 14. **A shared column with no rendered meaning does not stay meaningless; it accumulates private meanings, and the first surface to render it exposes all of them at once.**

Rules that keep this honest:

- **Never read `priority` directly for display.** Call `urgencyFromPriority()` — that is what lets an explicit enum column replace bands later without touching a single surface.
- **Colour is never the only signal.** Every non-normal band also carries a distinct icon (`components/urgency-icon.ts`) and the word itself, and both themes are declared explicitly. A red border alone is unreadable in greyscale and unsayable by a screen reader.
- **Urgency changes how a chip LOOKS, never what a click DOES.** The chip still only expands; only the card's verb button runs anything (THE INTENTIONAL-ACTION LAW above). An urgent assist that auto-ran would be the exact violation the law exists to prevent.
- **The manager's urgency filter is server-side** (`minPriority` / `maxPriority` on `AssistsQuery` → `priority >= min AND priority < max`), so the band's row count and paging agree with the header. A per-page column filter would quietly lie; the `priority` column therefore renders the band but does not filter.
- **A domain severity score is not an urgency.** Map it onto a band in the producer (one constant map), and use `rank` to keep the domain's own ordering. The live example is `private.sweep_marketing_finding_assists()`: `critical → 20+scope`, `high → 15+`, `med → 10+`, `low → 5+`, `info → 0+` — so only a genuinely broken site (5xx, 4xx, https enforcement, robots conflicts) is red, and worst-first still holds everywhere.
- **The aidream twin is `assist_priority()`** in `aidream/services/assist_support.py`, beside the shared dedupe/addressee plumbing. Same bands, same bar, same clamp; it raises on an unknown band rather than defaulting to `normal`, because silently downgrading an alarm is the failure this column now controls.

| Producer                                                                     | Band     | Why                                                                                               |
| ---------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| `workflow.human_decision`                                                    | urgent   | The run is stopped; only this person restarts it. The case everything else is calibrated against. |
| capture-failure (aidream)                                                    | urgent   | Replay/hindsight are losing inputs right now, silently.                                           |
| `seo.finding_rollup.*` critical                                              | urgent   | The site is actually broken (5xx / 4xx / https / robots).                                         |
| `workflow.run_recovery`, `tasks.overdue_pileup`, backlinks damage, GSC decay | elevated | Real and worth soon; nothing is blocked.                                                          |
| competitor confirm, notes pileup, review backlogs, `hindsight_finding`       | normal   | Queues and proposals.                                                                             |

## DB

`platform.assists` (entity token `assist`, RLS via `iam.apply_rls` variant `entity`, visibility `personal`). Producers set `created_by` = the addressee. Migrations: `migrations/platform_assists_ledger.sql`, `migrations/platform_assists_absorb_capabilities.sql`, then `migrations/platform_assists_source_suppression.sql`. Unique live-pending index on `dedupe_key`.

**Suppression stays on the ledger.** A finite `suppressed_until` is one assist snoozed until then. PostgreSQL `infinity` means the whole `source_key` is silenced until the user reverses it; the required reason lives in the row's existing base `metadata`, leaving the user-authored `decision_note` exclusively for actual assist decisions. `private.inherit_assist_source_suppression()` applies that record to every future insert from the same producer, so a new dedupe key cannot punch through the mute. The card offers **Every assist like this**; `/assists` shows every silenced source and **Turn back on**. No suppression table, status, column, chip, or handler was added.

**The absorbed columns** — every one is read and written by the client. A column with no consumer is a half-landed migration, which is exactly what this table carried until 2026-08-13:

  layer is what moved here (`features/marketing/findings-assists-producer.ts`,
  gap `G-FINDING-ASSIST`). The doctrine's own words: each system "keeps its

  and schema-moved on purpose, with zero runtime consumers — which under
  `/policies/unfinished-work-alarm.md` means **a previous agent was

## Producer rules (non-negotiable)

1. Always set a `dedupeKey` and exclude keys the addressee accepted or dismissed before emitting — client producers use `filterUndecidedKeys`; server/swept producers enforce the same ledger check in their transaction. A user's decision is durable and re-noticing must not resurrect the chip.
2. Cap per-sweep emissions; set `expires_at`.
3. Cheapest-first (canvas doctrine rung 5): deterministic state checks before any model call.
4. The action must DO something real. A chip that opens a blank chat is banned.
