# PDF — the document domain feature

**Status:** Active consolidation (2026-06). One canonical home for every PDF concept; the studios are surfaces, not features.
**The rule that created this feature:** `features/pdf-extractor`, `features/pdf-demo`, and the PDF parts of `features/file-analysis` were never features — they are *surfaces* of this one domain. New PDF capability lands HERE; surfaces compose it. Never add a sibling `features/pdf-*`.

## Canonical parts (use these; never re-create)

| Need | Use | Path |
|---|---|---|
| Call any `/utilities/pdf/*` endpoint | `usePdfClient` (typed; 422-aware errors; blob/JSON content-type guard) | `api/client.ts` |
| Build a request source | `buildPdfSource` / `buildSecondSource` — **`media:{file_id}`, never `cld_id`** (the keystone bug class) | `utils/source.ts` |

| Render a PDF | `PdfDocumentRenderer` (THE viewer) / `PdfPreview` wrapper | `components/viewer/` |

## Data model — the bridge (2026-06-11)

One physical PDF = `cld_files` row. Two derived families, now sharing identity:
- **Extractor:** `processed_documents` (clean_content, lineage via `parent_processed_id`) → `processed_document_pages` (raw/clean text, blocks/words, `is_continuation`, sections — the fidelity-rich canonical page table).
- **Analysis:** `file_pages` (user decisions: exclude/rotate/override, thumbnails) → `file_analysis_result`, `file_page_annotations`.
- **The bridge:** `cld_files.canonical_processed_document_id` (backfilled 27/27; trigger-maintained: new docs fill empty bridges, new pages auto-link `file_pages.processed_document_page_id`, new file_pages self-resolve). **One read perspective:** `public.pdf_unified_pages` (security-invoker view).
- **Redaction compliance:** every redaction writes `pdf_redaction_audits` (applied + wired 2026-06-11); reversible spans in `redaction_mapping` (client-held AES keys); `pdf_redaction_key_escrow` is the org-recovery data model — **write path intentionally unwired pending the security team's KMS interface** (keys must be wrapped, never raw).

## Surfaces (consumers of this feature)

`/tools/pdf-extractor[/[id]]` (extractor studio + window-panel) · `/files/f/[id]` (viewer tabs) · `/files/f/[id]/studio` (Analysis Studio; mobile = stacked layout) · `/demos/pdf-processing/*` (27 live API test pages) · RAG `PdfPane` · **Source Inspector** (`features/rag/components/source-inspector/`, overlay `sourceInspectorWindow` — a RAG/citation surface that renders `PdfPreview` at the cited page beside the page's raw/clean extraction + matched chunk; composes pdf parts, never forks them) · code-editor preview · public-chat optimize prompt. All reachable from each other via `PdfSurfaceSwitcher`.

## Invariants

- Sources go through `buildPdfSource` — raw `media`/`cld_id` literals are the bug class that broke the platform (Pydantic silently drops unknown fields; `extra="allow"`).
- Pages are 1-based everywhere on the wire.
- `persist_output=true` switches binary endpoints to a JSON envelope — `usePdfClient.postPdfBlob` guards content-type so an envelope/error can't masquerade as a PDF.
- Derivative ops NEVER mutate the source file; UIs must say so (ConfirmDialog + note pattern, see ManipulationPanel/PagesPanel).
- In-place page ops (`rotate/exclude/include` via file_analysis router) are metadata-only on `file_pages`; callers refetch after success.
- Uploads only via `fileHandler`; no `supabase.storage` here.
- Backend preset/pattern/region ids are stable contract strings — never hardcode FE copies.

## Change Log
- 2026-07-06 — **`storage_uri`/`file_uri` eradicated from the PDF cluster.** Native storage locations (`s3://…`) are SERVER-ONLY (see `features/files/FEATURE.md`): no `processed_documents` read selects `storage_uri` anymore; `PdfDocument.source` / `StudioDocSummary.source` deleted with every consumer; derivative inserts (`features/pdf/services/saveDerivative.ts`, now also backing the reader's crop/reorder saves) no longer write `storage_uri` (the column is nullable; the backend resolves bytes via `source_kind='cld_file'` + `source_id`). The source wire (`features/pdf/utils/source.ts`, `streamPdf.ts`, `MediaRef` docs) sends only `media.file_id` / `media.url` — the `file_uri` member is gone; `buildPdfSource` resolves cld_file docs only (no-source docs get the existing re-upload empty state). "Open original / View Original / Source File" everywhere routes through `/files/f/{sourceId}`. `PdfStudioUrlViewer` deleted (caller-less once `doc.source` fell); `SyncedPdfTextView` iframes (which never worked for `s3://` rows) replaced with a "open in PDF Studio" note.
- 2026-07-06 — **Upload → new-doc routing made reliable.** Submitting a PDF from the studio (empty-state hero or `+ Add` drawer, desktop + mobile) sometimes never navigated to the new doc even though the server finished and the `processed_documents` row existed. Two root causes, both fixed in `features/pdf-extractor`: (1) the hand-off was gated on the `processed_documents` detail fetch succeeding — a read that can transiently return `null` right after the row is created blocked routing entirely; `usePdfExtractor.extractFiles` now fires a new `onFirstDocId(docId)` callback from **inside** the stream the instant the first file's `doc_id` lands (before/independent of the fetch) and resolves with all completed ids, and `PdfStudioUpload` routes off that instead of a fragile `tabs`-watching effect (deleted, along with its stale-closure session tracking). (2) `fetchProcessedDocument` cached `null` misses for the full 30s TTL, so the destination reader would 404 the just-uploaded doc for 30s; it now caches hits only, so a transient miss self-heals. NOTE: batch-extract emits `doc_id` only at each file's completion (no incremental page persistence), so the reader opens the moment the first file is done — true mid-extraction "live" streaming into the reader needs a server change (early `doc_id` + incremental page rows or realtime).
- 2026-07-06 — **Sidebar doc menu parity with `/files/f`.** Cloud-file-backed rows in the left rail now use the canonical `FileContextMenu` (rename, share, visibility, duplicate, PDF surfaces, RAG actions, delete file, etc.) plus extractor extras (**Copy extractor link**, **Remove from extractor**). Right-click uses `FileRowContextMenu`. Legacy/non-cloud docs keep the studio menu with rename added. Shared rename path: `renameStudioDocument` + `StudioDocRenameDialog`. When every per-page `cleaned_text` row is empty, the cleaned reader pane's banner now offers **Run AI Clean** (same action as the toolbar) instead of **Re-run pipeline** — pipeline is for raw re-extraction, not missing clean content. Raw pane still offers pipeline.
- 2026-07-02 — **AI output now renders through the canonical rich-document engine (thinking handled, markdown rendered).** The extractor's AI-generated content (whole-document clean + full-pipeline template output — live-streaming and final aggregate) was displayed in raw `<pre className="font-mono">` blocks, so the model's `<thinking>`/`<reasoning>` spilled as literal text and markdown didn't render. New single-purpose renderer `features/pdf-extractor/components/PdfAiContent.tsx` wraps `MarkdownStream` (the same engine that renders assistant chat messages), so AI output renders as markdown with the model's chain-of-thought collapsed into a `ThinkingTrace`. Wired into the live-stream + aggregate-cleaned sites of `PdfExtractorWorkspace` (`AiCleanView`), `PdfStudioReader` (`TextPane` streaming + cleaned-aggregate + legacy fallback), and `PdfStudioMobile` (streaming + cleaned aggregate). RAW extracted PDF text stays monospace (it is not AI output); per-page cleaned views and the copy-overlay preview stay monospace for now (they coexist with search-highlight / synced-scroll / inline-edit). Cleaned-aggregate search highlight is intentionally dropped in favor of proper rendering. Part of the app-wide "single canonical path for streamed content" work — see `features/agents/docs/STREAMING_SYSTEM.md` (2026-07-02).
