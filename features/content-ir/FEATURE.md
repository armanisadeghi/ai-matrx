## Load-bearing invariants

- **One shape, one live kind — enforced at three seams, and they are the SAME rule stated three times (D164).** A hand-authored kind (`metadata.family='user_authored'` OR `metadata.user_authored=true`, not `is_contract_artifact`) may not carry an `emitted_fingerprint` that an ACTIVE hand-authored kind already owns — the render registry (`matchKindForSchema` / `buildKindFingerprintIndex`) is first-writer-wins, so the loser silently DISPLAYS as the winner. Refused at **mint** (`_duplicate_shape_refusal`, matrx-ai `kind_authoring.py`, on `kind_create` + `kind_update_schema`), at **activation** (the `uniqueness` leg of `content_ir.evaluate_kind_activation`), and at the **DB floor under both** (`content_ir.guard_kind_shape_uniqueness()` BEFORE INSERT OR UPDATE — the only leg a second writer, `service_role`, or a future tool cannot walk around). **Change one, change all three.** The scope is deliberately narrow: machine-minted `is_contract_artifact` snapshots and the `*_io` families collide by construction and MUST keep working — never widen it to them.
- **Hosts find regions; the parser owns the inside.** The accumulator (stream) and splitter (DB) detect where a JSON region starts/ends; a fresh parser per region makes single-root true by construction. After a host closes any Markdown, code, XML, JSON, or prose container, both paths run the same `surfaces/embedded-kind-json.ts` recovery pass: every complete JSON object with a direct non-empty `__kind` is promoted to its own Content IR region, while the surrounding bytes remain ordered and lossless. Registered root-kind surfaces and artifacts keep ownership of their nested composition. The Python block detector mirrors this boundary exactly. The host remains the region-end oracle until Phase 7.
- **Pushdown discipline:** commit → descend → never re-ask → backtrack. Speculative descent commits a child's kind the instant `{` opens when the parent schema predicts it (`{type:"object",kind}`, single-member `itemKinds`, `expectedRootKind`); `__kind` confirms, re-tags (allowed sibling), or drops THAT node to raw. Objects under a predicting parent need no `__kind` at all.
- **Node-scoped errors never kill a stream.** Duplicate keys, schema violations, disallowed itemKinds → that node goes `raw_object`, the parent keeps parsing. Only grammar errors are region-fatal → the region degrades to a code block.
- **Zero data loss:** unknown keys NEVER merge into snapshot values — they ride `residue.extra` (root residue + per-node residue in `nodeIndex`). Wire round-trip = `reconstructRegionValue`.
- **Stream ≡ static:** the accumulator's streamed envelope and the splitter's one-shot envelope are byte-identical (fingerprint included) — enforced by `__tests__/stream-splitter-parity.test.ts`. Pending-schema nodes resolve to raw at region end so envelopes are deterministic; upgrade-in-place is a live-region feature.
- **The envelope rides `metadata.__ir`** on render blocks and splitter blocks. `data` stays reserved for the routed component's serverData. Live-stream consumers read it from Redux via `selectKindEnvelope(requestId, kind?)` (`active-requests.selectors.ts`) — **never a second parallel parse of answer text** (see § No bespoke stream renderers). GOTCHA: a `displayMode:"direct"` launch's thunk resolves only AFTER the stream ends — derive the live requestId from `selectConversationRequestIds`, never from `.unwrap()` (the starvation bug behind the 2026-07-03 flashcards fix).
- **Progress `data.content_ir` is canonical content, not feature-private data.** Durable pipeline endpoints may attach a complete structured value to an ordinary typed `data` event so domain hooks can update their own state. `processStream` promotes and registry-routes that nested value through `redux/progress-data-block.ts` into a complete render block carrying `metadata.__ir` and the canonical component projection; `selectUnifiedSlots` emits the paired block at that data event's exact chronological mandate. The ordinary data payload and timeline event remain intact. Features must not parse, route, or render this value themselves.
- **Reload never re-parses a committed region.** `assembleMessageParts` stamps every COMPLETE envelope (any engine) onto the emitted text part as an `IrEnvelopeCache` (`metadata.__ir = {v:1, blocks:{fingerprint→envelope}}` — `core/envelope-cache.ts`); the read boundaries (`normalizeContentBlocks`, `extractFlatText`) seed it into `registry/region-envelope-memo.ts` and the splitter reuses the envelope BY REFERENCE on exact fingerprint match. Server-built envelopes (`engine:"py-block-detector"`, on `render_block.metadata.__ir`) enter ONLY through `sanitizeInboundEnvelopeMetadata`: the PURE gate lives in `core/envelope-read.ts` (twin-safe, hook-injected side effects); `redux/render-block-envelope.ts` is the frontend host shell binding memo-seed + `captureError`. Valid → untouched + seeded; malformed → stripped + reported. Wire contract for aidream: [`docs/PYTHON_ENVELOPE_CONTRACT.md`](./docs/PYTHON_ENVELOPE_CONTRACT.md). Enforced by `__tests__/envelope-persistence.test.ts`.
- **A workflow node's output and a run's result arrive WRAPPED (`node_completed.wrapper`, `GET /runs/{id}.result`).** The packet is a self-describing `node_outcome` / `run_result` kind instance: which workflow, which node, timing, the kind verdict — and the data kind nested under `output`. The payload is never sent twice: `output` is `null` and `output_ref` names the frame field (`"output"`, or `"output.<node_id>"` on a run) to rehydrate from at the ingest gate. **Wrappers are visually transparent:** their components delegate the nested value directly to the registry; provenance remains diagnostic data and never wraps reader-facing artifacts. A wrapper component that re-implements a payload renderer is the exact corruption the layer model exists to undo. Complete-only, so it never touches the `__ir_partial` channel. Cross-repo wire contract: `/Users/armanisadeghi/code/common-docs/systems/content-ir-system/RUNTIME_WRAPPER_WIRE.md` — read it before touching how a node output or run result renders in ANY repo.
- **Structured content renders WHILE it streams (`metadata.__ir_partial`).** The server announces what it thinks a region is and what has arrived so far, as VALID CLOSED JSON, so a long structured answer fills in instead of showing a spinner. Three events, a CLOSED union on `state`: `partial` (repeatable, `kindState: "speculative"` — it may still become something else), `superseded` (terminal — completed as announced; the block's own `__ir`/content is the truth), `retracted` (terminal escape hatch — `becameKind`/`becameBlockType` name what it actually is, never a silent swap). **Every partial ends in exactly ONE terminal event** — that is what is SUPPOSED to make a stuck skeleton impossible, but it is a PRODUCER guarantee with three measured ways to not fire (the drain skips a block missing from the final list, the emitter drops every retraction once the stream is cancelled, a flush failure is swallowed). So the client does not trust it: `resolveProvisionalKindRender` takes `streamActive` and withholds once the stream is explicitly over, because no terminal can arrive after that and a still-open provisional is stuck by definition. Reader + wire gate: `@ai-matrx/content-ir` `wire/partial-kind` (`readPartialKindEvent` / `advancePartialKind` / `sanitizeInboundPartialKindMetadata` / `makePartialKindStalenessGate`), gated in `process-stream.ts` beside the envelope gate; the host route over it is `react/partial-kind-route.ts`. **The two channels never touch:** `__ir` means "validated against the registered schema" and is seeded into the region-envelope memo; a partial is provisional by definition and is seeded nowhere — which is how the complete-only law survives progressive rendering. A component routed a provisional value MUST tolerate missing required fields (`partial_unvalidated`). Cross-repo wire contract: `/Users/armanisadeghi/code/common-docs/systems/content-ir-system/STREAMING_PARTIAL_KINDS.md` — read it before touching progressive kind rendering in ANY repo.
  - **Rendering (`react/partial-kind-route.ts`, live since 2026-08-20):** a `partial` event wraps into a render-local `CanonicalBlockIR` and runs through the SAME `applyIrKindRoute` the final value uses, so the provisional value renders in the SAME component — a bespoke skeleton renderer would be a second render path and is banned. That envelope is placed on a render-local COPY of the block's metadata under `__ir` plus `__ir_provisional: true`; it can poison nothing, because `seedEnvelope` fires ONLY at the wire boundary. `BlockRenderer` stage 1.5 owns it, wrapped in `ProvisionalKindBoundary` (throw → scream + drop the kind back to withhold for the session + fall back to its loading skeleton) and `ProvisionalKindFrame` (a quiet "Still arriving" chip on the block's top border, zero layout cost).
  - **THE POSTURE — withhold by default, opt in per kind.** A provisional value may be missing required fields, so nothing is routed one unless its registry definition declares `partialReady: true` (plus `{ provisional: true }` on its `makeCompleteEnvelopeBridge` — a test pins the pair, because a facet promising a live fill-in over a bridge that declines every streaming envelope is a skeleton that never fills). Withheld kinds keep today's loading skeleton; so does a frame whose bridge declines a value too thin to render. First opt-in: `quiz_set`. Adding one = audit the component for absent fields, flip both flags, verify in the browser.
  - **Terminals are EVENTS, never inferred.** `superseded`/`retracted` produce no provisional render, so the final value replaces it in the same frame with no flicker. Never infer the terminal from the arrival of `__ir`: a completed block often has none (unregistered kind, schema drift, cold catalog) and the skeleton would stay up forever in exactly those cases.
  - **Staleness + carry-forward:** `makePartialKindStalenessGate()` (one per stream, in `process-stream.ts`) keeps the highest `seq` per block and CARRIES IT FORWARD. 🚨 **It must carry across a MISSING key, not just a stale one — that is the common case.** The producer clears `__ir_partial` on every stamp and re-adds it only when the value ADVANCED, so most events carry no partial key at all; since the reducer replaces the stored block wholesale, treating "absent" as "nothing to do" dropped the provisional render on almost every token and flickered the user back to the pending skeleton. The terminal is carried too, so a replayed `partial` arriving after it cannot re-open a closed region. Carrying stops at the terminal and only there.
- **Routing DISCARDS the raw block's own serverData.** An un-routed code block carries `data: { language: "json" }` (the accumulator's annotation), and the live-chat hop (`components/mardown-display/chat-markdown/render-block-to-content-block.ts`) maps `data` → `serverData` — so `applyIrKindRoute` derives routed serverData from the envelope bridge (cleared for bridgeless kinds), never from a truthy `block.serverData` (that junk-wins bug rendered "No flashcards available yet" on perfect payloads). Only a block ALREADY typed as the legacy target with its own serverData passes through. Enforced by `__tests__/kind-route-live-chat.test.ts` (real accumulator → real hops, all 8 families, mid-stream + post-materialization).
- **The package is the pure kernel** — no React/Redux/Supabase/browser imports. Matrix keeps only the host-only files under this feature. A host lookup is REGISTERED through the package seam (`setJsonRootKeyLookup`, wired once in `registry/kind-registry.ts`), never imported into the kernel and never passed per call.
- **Parity telemetry is loud:** accumulator region close deep-compares envelope vs `JSON.parse(content)`; mismatch → `captureError` source `content-ir` (Error Inspector).

## 🚨 No bespoke stream renderers — this is the kiss of death

**A surface NEVER parses, buckets, splits, or routes a live stream itself.** Streamed model output renders through the ONE pipeline: `MarkdownStream` → `EnhancedChatMarkdown` → `BlockRenderer` → `applyIrKindRoute` → the kind's component. That pipeline already owns chunk assembly, region detection, kind resolution, late-schema upgrade, loading states, finalization, and error recovery. Every one of those is a thing your surface will re-solve wrong.

**Banned outside this feature, no exceptions and no size threshold:**

- Calling `useLiveJsonRegion` / `openParseSession`. **`useLiveJsonRegion` is internal.** It is not a public primitive, and no feature may consume it.
- Bucketing raw chunk text into per-phase string buffers.
- Splitting a text buffer into "segments" so each payload gets its own region.
- Reading an envelope and hand-picking a component, or hand-building serverData.
- Deciding when a stream is "done" for render purposes with your own signal.

## 🚨 THE CANONICAL COMPONENT LAW — one shape, one component

**No bespoke stream renderers has a twin, and it is violated far more often: a registered shape may be rendered ONLY by its kind component.** The stream rule protects how data ARRIVES; this one protects how it LOOKS. Both exist for the same reason — one implementation that everyone improves, instead of N that each rot alone.

**The law.** If a kind is registered, its component renders it **everywhere** — chat, a live run, a form, a side panel, a preview card, a summary row. A hand-built renderer for that shape is **banned**, no matter how small, how "just a preview", or how specialized the surface feels.

**Why, concretely.** The duplicate always ships new bugs the canonical one already solved, it silently misses every later improvement, and it doubles the cost of every future change. Real example (2026-08-11): `features/marketing/content-plan/components/BriefEditor.tsx` re-implemented the `page_brief` kind by hand _on the very page whose run renders `PageBriefBlock` in the window beside it_ — same data, two renderers, two designs, and the duplicate crushed full-paragraph directives into one-line textareas.

**The four things people reach for a bespoke component to get — all of them belong IN the kind component:**

| You need                                               | Do this                                                                                                                                                                                  |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Only PART of the shape (just the angle, just the list) | **Split the canonical component into per-field child components; the parent composes them.** Render the child. Never re-render a slice by hand.                                          |
| It editable — add / remove / reorder / sort / filter   | Build it into the kind component. That is what kind components are FOR. Exemplar: the keyword kinds.                                                                                     |
| An action on it ("Use this brief", "Apply")            | The kind-component action registry — [`react/actions/kind-action-registry.ts`](react/actions/kind-action-registry.ts) + `useKindActionRunner`. Not a button on a bespoke card beside it. |
| It to look different here                              | Props on the canonical component. If the difference is real, every surface benefits from it.                                                                                             |

**Parent/child is the escape hatch, and it is the ONLY one.** A `page_brief` is angle + brief + must-not-cover + concerns. Wanting those in four places is a reason to build four child components under one parent — not a reason to hand-roll a fifth renderer.

**Arman's ruling, 2026-08-11, in anger:** exceptions exist but require his explicit approval, per surface. **No agent may grant itself one.** Not using the canonical component is against the rules — full stop.

## 🚨 THE FLOOR — an unregistered shape still looks good

**The guarantee changed on 2026-08-18, and this is the sentence to read: a shape no longer has to be REGISTERED to render well.** `MarkdownStream` is unconditional — any text in, good output out, no registration — and that is exactly why it never fails. The Shape System is a REGISTRY, so looking good depended on three independent things all being true (a curated `output_kind` rather than an auto-derived `action_io_*` / `workflow_io_*` contract kind; an ACTIVE web `kind_component`; a payload that validates), and missing any one dropped the payload to the floor. **The floor was `JSON.stringify` in a ```json fence.** Measured on one real production run (Study Pack v1, `fedd6591-…`): **2 of 23 steps rendered as components, 19 rendered as JSON** — developer artifacts handed to a non-technical Subject Matter Expert.

**The floor is now `StructuredValueView`** (`components/official/structured-value/StructuredValueView.tsx`): ANY JSON value as a human document — long strings as prose through the canonical markdown renderer, uniform object arrays as a sortable/filterable table, scalar arrays as lists and short ones as chips, nested objects as titled sections with humanized keys, `file_id` / media refs through `InlineMediaRef`, UUIDs and dotted enum reprs given their real treatment, empty fields as one word. It is recursive with a size bound (past ~40 KB serialized it renders in the capped density, where every cap carries an in-place "+N more"), it strips the internal `__kind` discriminator from what the reader sees, and it always offers **"Show the raw data"** — the JSON inspector, one click away, for US.

**A curated `kind_component` is now an UPGRADE, never a prerequisite.** THE CANONICAL COMPONENT LAW is unchanged and still wins: a registered kind's component renders it everywhere. This is only what happens BENEATH that decision — never a second renderer for a shape that has one.

**It is not a new engine.** The recursive value renderer already existed as the tool-result field library (`features/tool-call-visualization/result-fields/` — `detectResultShape` + `ResultValue` + `KeyValueGrid` + `ResultTable` + `ResultMedia` + `ResultJson`).
