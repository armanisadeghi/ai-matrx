## The model

**1 atom** — the **Shape**: a named, versioned structure. Home: `content_ir.kind_definition` + `kind_edge`, read via `kind_definition_version`.

**Target: 7 assets per independently usable Shape:** schema · skill(s) · content block · output component · input component · samples (`kind_example`) · Pydantic mirror. Nested-only and data-only kinds have explicit structural exemptions; current coverage is generated in `SHAPES_STATUS.md` and summarized cross-repo in the system-of-record.

**Target: 3 machines:** detection (`kind_surface` should drive every Shape surface and normalize it to canonical `__kind` JSON at the boundary) · registry/resolver (`kind_component`: (kind, platform, role) → component) · artifact + state. Detector bootstraps generate from `kind_surface` for both runtimes (see "Coverage gates"); host-literal deletion is gated on the Wave-2 ratchet, and full artifact adoption remains incomplete.

**Target: 4 consumer families:** agent outputs · workflow node I/O · tool inputs/results · custom apps. Workflow kind primitives are live; adoption across nodes/actions and the other families is incomplete.

**THE KEYSTONE — convergence at detection.** A Shape arrives on many surfaces (`__kind` JSON, XML tags, fences, tool results, markdown). The instant a detector recognizes Shape X it emits the canonical `__kind` JSON; the arrival format is discarded. Below the boundary everything is format-agnostic **by construction**. Split-per-format assets (skill, content block, detection) sit ABOVE the boundary; shared assets (schema, components, samples, pydantic, artifact/state) sit BELOW.

## The posture (read before judging any inventory)

- **Importance inversion.** What adheres today (flashcards, quiz) was the low-stakes testbed. What doesn't adhere (Matrx Actions, the XML render pipeline, the variable form system, tool results) is the mission-critical production material that was deliberately kept off the system until it had a real home. **Adoption = bridging real systems IN, not polishing testbeds.**
- **Borrow, don't conquer.** The render pipeline (`content-splitter-v2` + accumulator) transitions to **dual-mode**: XML stays a first-class *input surface* permanently (LLMs emit it easily); `__kind` JSON is the *internal* form. Content blocks are a borrowed delivery vehicle into the user's context menu — we don't own that system. The form system (`VariableDefinition` → `VariableInputComponent`) is production — the input-component asset is a **bridge** to it, never a new form builder.
- **Matrx Actions is the elder sibling** — the origin system this generalizes, live in production. Its 12 invariants are constraints on us (envelope detected by `matrx_version` presence only; position invariants; handler = only side-effect path; no parallel encodings; …). The only sanctioned touches near it: the kind-slug collision guard and a ` ```matrx ` `kind_surface` row routing to the protocol handler. Actions↔kinds convergence is deferred (Arman's call); `kind_definition.metadata` carries the safety vocabulary (`category: pure|side_effect|sensitive`) so either direction needs no schema change.

## The Convert Pattern (ratified 2026-07-15) — some content does NOT start as a `__kind`

**Markdown-first content renders through a rich generic component; promotion to a kind/artifact/live entity is an explicit USER action (a button) — never automatic.** Adoption leans maximally non-breaking, and this is the one deliberate ceiling: when the plain form IS the content contract, detection would destroy value, not add it. You click to convert.

- **`table` is the exemplar — permanently `scalar_generic`, never auto-kind.** The markdown table is the core content (it stays in `cx_message.content`, so the model's history matches what the user sees); `StreamingTableRenderer` renders it richly (edit, sort, export, save). **Convert to table** (`features/canvas/artifact-types/renderers/TableArtifact.tsx`) links a real `udt_datasets` row via `createDatasetFromTable`, after which the live realtime `UserTableViewer` renders from the dataset — and **Revert** unlinks it (dataset kept, markdown untouched). The ruling is encoded in the crosswalk `table` rationale (`generate-content-vocab-crosswalk.ts`) and aidream `envelope.py` `NON_ENVELOPE_BLOCK_TYPES["table"]` — do not "fix" either by registering a table kind.
- **The shipped convert machinery is `features/canvas/materialization/`** — notes fence/kind-JSON → artifact (`useNoteArtifactMaterialization` → `materializeBlocks({system:"note"})`, the "Convert blocks to artifacts" editor action) and chat attach/detach (`attachBlockAsEditableContext` / `unbindArtifact` / `flipMessageToDbRender`). Build new convert affordances on it; never a parallel path.
- **Decision rule for a future kind — convert-pattern vs auto-kind.** Choose **convert** when the plain/markdown form is the durable contract (round-trips the DB, feeds model history), rich rendering already works without identity, and promotion creates a NEW stateful entity (dataset, artifact, task). Choose **auto-kind** (`kind_surface` detection) when the payload is born structured and the win is validation + shared rendering with no ownership change. Every convert MUST have a way back (Revert; the original text is never destroyed).
- **Registration without detection is legal and useful.** The 2026-07-17 candidate registration (chart, map, stats, diff, search_results, fetch_results, categorization_result) gives splitter/data-event blocks identity, validation, and coverage with ZERO surface rows — arrival and rendering unchanged. Identity and detection are separate decisions.

## Input components (D1, live 2026-07-15)

**The canonical input component is `features/content-ir/input/KindInputForm.tsx`** — resolver-gated (`resolveComponent(kind,"web","input")`), R5-bridged (kind fields → `kindFieldsToVariableDefinitions` → the production `VariableInputComponent`), validated by `validateStructuralLeg` (the activation gate's own ajv leg) before `onSubmit` ever fires. **Never build a second kind-input form** — consume or extend this one; it is heavy (ajv + the agent input stack), so load it `next/dynamic({ ssr: false })`.

- **Routing law** (pure, tested): `input/kind-input-resolution.ts#decideKindInputPath` — unknown kind / missing binding / inactive binding / unrouted dedicated key → **loud refusal** (`captureError` source `content-ir`, visible error card, never a guessed form). `generic_structured` + stored fields → bridged form; no stored field list (python-owned / non-object roots) → **whole-instance JSON mode** (one textarea validated against `emitted_json_schema` — the documented v1 fallback, same posture as the bridge's structured-JSON textarea).
- **Coverage classes** (`kind_component` role='input', web; migration `migrations/content_ir_input_component_bindings.sql`, applied + ledgered): **generic** = 20 active display roots + 16 workflow-I/O structural kinds (36 DB rows) — plus a compiled input floor for EVERY system kind (`system-components.ts`, DB rows override). **Non-interactive by classification** = the 635 data-only generated contracts (tool_io/action_io/agent_io/workflow_io) — machine-filled; fabricating forms for them is forbidden. **Dedicated** = none yet; the mermaid workbench was evaluated and rejected (artifact surface, no controlled onChange) — a dedicated binding lands only WITH its `KindInputForm` routing, since unrouted keys refuse.
- **Value layer**: `input/kind-input-values.ts` (pure; promoted from admin/) — variable string-space → kind typed-space coercion, instance assembly, ajv error attribution. Shared by the form and the admin Inputs lab.
- **Proof surfaces**: `/administration/kind-registry/<kind>?tab=try-input` (the form consumed as a feature would) and `?tab=inputs` (the bridge diagnostics lab). Tests: `__tests__/kind-input-form.test.ts` (key parity, coverage, routing law, valid/invalid emission).

## Coverage gates (A1, live 2026-07-15)

- **Every named content vocabulary item is classified** — `scripts/shape/content-vocab-crosswalk.json` (GENERATED, never hand-edited) maps every BlockType value, render-block union member, artifact alias, detector token, live kind slug/surface token, and generated contract to exactly one of `shape` / `protocol` / `scalar_generic` / `intentionally_opaque`. The classification **authority** is the rule tables in `scripts/shape/generate-content-vocab-crosswalk.ts`; an item no rule claims **fails the run**. Regenerate: `pnpm check:shapes:crosswalk:refresh`; drift-check: `pnpm check:shapes:crosswalk`.
- **The aidream contract inventory is a checked-in snapshot** — `scripts/shape/content-ir-contract-manifest.json`, regenerated by `pnpm check:shapes:manifest:refresh` (shells to aidream's `sync_content_ir_contracts.py --json`; fails loudly without aidream, never silently).
- **The render-block vocabulary is generated, both directions** (C3, live 2026-07-15). Server data-event render blocks (`audio_output`, `function_result`, `value_store_stored`, …) generate into `stream-events.ts` from aidream `matrx_connect/context/data_render_blocks.py` — classification-grouped (`ServerProtocolRenderBlock` / `ServerScalarGenericRenderBlock` / `ServerShapeRenderBlock` / `ServerOpaqueRenderBlock` → `ServerOnlyRenderBlock`); the crosswalk build FAILS if the generated classification diverges from the rule tables. Client-splitter-only types live in `components/mardown-display/markdown-classification/processors/utils/client-blocks.ts` (owner: the splitter). `types/python-generated/missing-types.ts` is DELETED — never recreate a hand-maintained render-block type patch.
- **Detector bootstraps are generated from `kind_surface`, both runtimes** (C2, live 2026-07-15). `pnpm check:shapes:surfaces:refresh` reads live ACTIVE `kind_surface` rows and writes `registry/system-surfaces.generated.ts` (the registry's compiled floor — `system-surfaces.ts` re-exports it, NEVER hand-add an entry) AND aidream `packages/matrx-ai/matrx_ai/processing/blocks/kind_surfaces_generated.py`, both embedding one byte-identical `KIND_SURFACE_BOOTSTRAP_JSON` payload. `pnpm check:shapes:surfaces` fails on committed-vs-live drift or cross-runtime payload divergence; parity tests live in `__tests__/surface-bootstrap.test.ts` (FE) + aidream `packages/matrx-ai/tests/test_kind_surface_bootstrap.py` (also reconciles Python host literals → `BLOCK_KIND_MAP` kinds, with a shrink-only `KNOWN_PYTHON_HOST_GAPS` ratchet). The doctor red `surface-token-undetectable` fires when an ACTIVE surface token exists in NO host literal. The hard-coded host literals STAY until the Wave-2 enforcement ratchet.
- **The chat renderer dispatches BY classification** (C3 renderer half, live 2026-07-15). `BlockRenderer` routes through the declarative registry `components/mardown-display/chat-markdown/block-registry/block-dispatch.tsx` — one table per crosswalk classification, compile-time exhaustive against the generated unions (`satisfies Record<KnownBlockType, …>` + `AssertNever`), loud runtime path for unregistered types (`reportUnregisteredBlockType`). NEVER add a switch case — classify the type (matching the crosswalk) and register it in the right table; `__tests__/block-dispatch.test.tsx` fails on crosswalk↔registry classification drift.
- **The doctor consumes both**: a kind slug / detector token / surface token missing from the crosswalk is a RED `vocab-unclassified`; manifest↔catalog divergence (either direction, active rows) is a RED `contract-gap`; a missing/corrupt crosswalk or manifest snapshot is a RED `coverage-input-missing`.
- **Every live gather feeding these gates is privilege-complete, never viewer-RLS-scoped.** The baselines (manifest + snapshot) are service-key-complete, and generated contract kinds follow their SOURCE's org (an agent_io kind lives in its agent's org) — an RLS-scoped read hides other users' org-homed kinds and fabricates `contract-gap` reds + snapshot-only drift. CLI scripts read with `SUPABASE_SECRET_KEY`; the admin board reads via the super-admin-gated `shape_doctor_gather` SECURITY DEFINER RPC (`migrations/shape_doctor_gather_rpc.sql`). Before trusting a board red, confirm it with the CLI (`pnpm check:shapes`) — CLI-green + board-red means a privilege-scoped read path, not a registry defect.
- **All four generated contract families (`action_io`/`tool_io`/`workflow_io`/`agent_io`) are data-only** — render assets `n/a`, `definition`/`example`/`gate_structural` fully enforced per kind. Reports aggregate them per family; the JSON snapshot keeps every row.
- **The recomputed gate strips `__kind` on BOTH sides** (`stripKindFromJsonSchema` in `shape-doctor.ts`) — agent_io response_format schemas require `__kind` while `validateStructuralLeg` deep-strips it from samples; the gate checks contract substance, indifferent to where the identity key travels.
- **Release gate:** `pnpm check:content-ir:strict` = crosswalk drift/coverage + twin drift (`pnpm check:content-ir:twin`, hashes the kernel sources against aidream's `TWIN_MANIFEST.json`; skipped LOUDLY without aidream) + `check:shapes --strict`.
