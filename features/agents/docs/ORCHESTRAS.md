# Orchestras

An **Orchestra** = one **conductor agent** presiding over **member agents**, each filling a gap in a bigger picture. Built entirely on the registered `platform.associations` system — **there is no `orchestra` table.**

> **Naming (2026-08-15, Arman):** this was called "Agent Set" while the name was a placeholder. It is **Orchestra** now; the managing agent is still the **Conductor**, its agents are still **members**.

## Data model — zero new tables

`agent` is a registered entity token (`platform.entity_types` → `agent.definition`). An Orchestra is two kinds of association edge, written ONLY through the registered chokepoint (`associationsService` → `assoc_add`/`assoc_remove`/`assoc_set_targets`):

| Edge | source → target | role | Carries |
|---|---|---|---|
| **Marker** | `agent:X` → `agent:X` (self-edge) | `orchestra` | Orchestra config in `metadata` (`accent`, `tagline`, `conductorPos`) + `label`. Its existence = "X is an conductor" (lets an **empty Orchestra persist**). |
| **Member** | `agent:X` → `agent:Y` | `member` | role title in the `label` column; `position` (order) + `metadata` (`gap` — the authored "what it does in this Orchestra" — and saved `pos`; `required` — the C-26 "Must be consulted" flag; `result_mode` — how its result comes back, D-40). |

**Direction is fixed: conductor = source, member = target.** This matches `assoc_set_targets` (operates from the source) and the org-auth gate in `assoc_add` (resolves org from the source agent's `organization_id`). The `(source, target, role)` unique key keeps the marker and member edges from ever colliding, and makes every write an idempotent upsert.

**The one read the assoc_* family lacks:** `orchestra_list()` (SECURITY DEFINER, `iam.has_org_access`-gated; `migrations/orchestra_list_rpc.sql` + `orchestra_list_drop_legacy_role_arm.sql`) enumerates the caller's Orchestras (marker rows) + member counts. A single Orchestra's full state loads via `associationsService.listForSources('agent', [orchId], 'agent')`, split by role.

The Orchestra's name/description ARE the conductor agent's — no duplicated identity. Tokens live in `orchestras/constants.ts` (`AGENT_TOKEN`, `ORCHESTRA_MARKER_ROLE`, `MEMBER_ROLE`).

**The rename is fully contracted.** Before 2026-08-15 the marker role was `matrx_set`. It was migrated in three ordered steps so nothing half-deployed broken: both repos shipped reading BOTH values → the 10 live rows were migrated → the tolerant read was removed. `matrx_set` is now at zero and nothing reads or writes it; `orchestra_list()` matches `orchestra` only, and `agent_set_list()` is dropped.

## Surfaces

- `/agents/orchestras` — list of all Orchestras (the savior list view). Entry from `/agents/all` ("Orchestras") and the per-agent **Add to Orchestra** card action.
- `/agents/orchestras/[conductorId]` — the **builder**: library rail (drag/click to add) + a **React Flow hub-and-spoke canvas** (conductor hub, member spokes, animated edges; drag to reposition — positions persist) **or** a `@dnd-kit` sortable **Grid** view + a **member inspector** (author each member's role/gap).
  - **Header:** the builder owns NO in-body header. It consumes the shared `EntityModeHeader` template (back → `/agents/orchestras`, Orchestra-name dropdown over the user's other Orchestras, `Canvas | Grid` mode nav, actions: library toggle / Run / Sync agent listings / Conductor / Orchestra settings) which portals into the shell header; on mobile everything collapses into the one `…` bottom sheet. Body is `h-full` + `pt-[var(--shell-header-h)]` — never a `calc(100vh − header)` (that produced the overlap + dead bottom strip fixed 2026-07-24).
  - **Canvas/Grid lives in the URL** (`?view=grid`), because the mode nav is href-driven; `activeModeHref` is passed explicitly since the two modes share a pathname.
  - **The library rail is a static column on `md+` and a slide-over below it**, toggled from the header (`PanelLeft`). 16rem of fixed rail on a phone left no canvas at all.
  - **Inspectors (right side, mutually exclusive):** every node carries a hover toolbar. A **member** node → **Quick look** (snapshot) + **Edit role** (→ `MemberInspector`: role title / gap / I/O). The **conductor** hub node → **Quick look** + **Conductor details** (→ `ConductorInspector`). The conductor inspector mirrors the member one (snapshot + `AgentIODetails` inputs/outputs + Open/Run) and adds the one thing unique to an conductor: **View system prompt**, which opens the Agent Advanced Editor restricted to the System Instructions tab (`useOpenAgentContentWindow({ tabs:["system"] })`) — the conductor's prompt is auto-generatable, so direct access from the builder matters. The shared I/O block lives in `AgentIODetails` (consumed by both inspectors — never duplicate it). The **Grid view** renders the same hub as a **non-sortable conductor tile** above the member list (`OrchestraMemberGrid`'s `ConductorTile` — not a member, outside the DndContext) with the same Quick look + Conductor details actions via the same `onOpenConductor` path; the whole tile is clickable because hover toolbars don't exist on touch and Grid is the mobile builder.

## Generating an conductor (for users without one)

Most users won't already have an conductor agent. The flow is **create-then-build**, NOT a modal full of agents (agent selection belongs on the builder's canonical rail, never a cramped picker):

1. **Name it.** `/agents/orchestras` → **Generate conductor** → `GenerateConductorDialog` is a QUICK name + accent prompt only. `useCreateConductor` then **copies the "Agent Conductor" template** (`b06689e3…`) via `agx_create_agent_from_template` (POST `/api/agents/templates/[id]/use`) — a new agent owned by the caller, shipping the template's **empty `<available_agents>` placeholder** — renames it, creates the (empty) set, and opens the builder. Org: the copy is created org-less but the DB `_stamp_org_default` trigger backfills the caller's personal org (accessible) — the flow never overrides it (members can be shared/foreign-org).
2. **Add agents in the builder** on the canonical rail (search / Mine-Shared-All tabs / category-tag filters / peek / drag-drop) — the same system as `/agents/all`.
3. **Sync the prompt — one button, one AI pass** (`syncConductorPrompt`). The builder detects a **template conductor** (`useConductorPromptStatus`: its prompt has the `<available_agents>` markers) and shows a **Sync agent listings** action (amber-pulsing when the listed agent ids **differ from the current members**). Marker-pre-checked before the slow LLM run, then:
   - **(a) Describe every member's role.** The whole Orchestra is dumped to the **Orchestra Role Describer** (resolved from the `orchestras.role_describer` slot — never a raw UUID; HEADLESS: ephemeral, `displayMode:"background"`, `autoRun:true`, var in `runtime.variables`). Each member entry carries its config (`agent_name`, `agent_description`, `system_prompt` from `messages`, `inputs`, `output`) **plus its CURRENT Orchestra role** (`current_role_title` / `current_gap`). The describer returns `{id,role_title,gap}` for **every** member (`parseRoleDescriberOutput`): it **fills** the blank ones, **fixes** the wrong/outdated ones, and **confirms** (keeps) the already-accurate ones. The role/gap cannot be derived mechanically — a field may be empty or wrong — which is exactly why an AI pass, not a deterministic copy, produces it.
   - **(b) Write role/gap to the member EDGES.** Each corrected `{roleTitle,gap}` is saved via `saveMemberMeta` (canonical association write — `label` = role title, `metadata.gap` = gap), only when it actually changed. A member the caller can't edit (RLS) is skipped, not fatal; the changed count surfaces in the toast.
   - **(c) Build `<available_agents>` in CODE** from the corrected role/gap + each member's declared inputs/outputs (`buildAvailableAgentsBlock`) → `injectAvailableAgents`. **This block is deterministic ASSEMBLY of AI-corrected data — NOT an LLM re-analysis.** One clean `<agent id="…">` block per member (Role / Fills / Inputs / Output), no duplicated id, no `<agents>` wrapper, no model prose. This replaced the old "Agent Description Generator" listing, which duplicated the id and ignored the authored role/gap.

   **Reasoning never leaks into the prompt:** the describer's headless `responseText` is derived via the canonical `deriveAnswerText` (in `launch-agent-execution.thunk.ts`'s `pollForCompletion`), which EXCLUDES `thinking`/`reasoning` blocks. A raw render-block join (the prior bug) wrote the model's chain-of-thought straight into `<available_agents>`.

   **No `<available_agents>` section → "Enable sync", never a silently-missing button.** The Sync action is gated on `useConductorPromptStatus().isTemplate` (the prompt HAS the markers). When an conductor is loaded but its prompt has no section (`ready && !isTemplate`), the builder shows a **yellow "Enable sync"** action instead of hiding everything: one click runs `enableConductorSync` → `conductorService.ensureAvailableAgentsSection` (idempotent — appends a labelled empty `<available_agents></available_agents>` to the system message), then opens the **Agent Advanced Editor restricted to the System Instructions tab** (`useOpenAgentContentWindow({ initialTab:"system", tabs:["system"] })`) for review. `fetchFullAgent` refresh flips the action back to the normal "Sync agent listings". The warning pill uses the header template's new `warning` variant (`EntityHeaderAction.warning` → `bg-warning`).

Agents load ONCE across the whole surface via `useEnsureAgentsLoaded` (the canonical TTL-guarded `initializeChatAgents`) — **never** `fetchAgentsList` directly (that refetches every mount). Files: `orchestras/conductor/{constants,conductorService,thunks,useCreateConductor}.ts` + `hooks/{useEnsureAgentsLoaded,useConductorPromptStatus}.ts`.

**Injection invariants (load-bearing):** the marker is `<available_agents>…</available_agents>` (`AVAILABLE_AGENTS_RE`). NEVER replace it with a plain string — the assembled block can contain `$`, which `String.replace` interprets (`$&`/`$1`/`$$`); use a **function replacer** (`injectAvailableAgents`). Absent marker → **loud failure**, never write a malformed prompt.

**Future — auto-add agents (documented, NOT built):** when a user creates a member agent FROM a template, auto-generate that agent's `<agent>` entry and append it to every conductor whose Orchestra it joins. See [`ORCHESTRAS_ROADMAP.md`](./ORCHESTRAS_ROADMAP.md).

## Runtime delegation — member-as-tool supervisor (P0+P1)

Running an conductor makes it **call its members as tools** and weave their outputs into one answer (the industry supervisor/worker pattern). This reuses aidream's EXISTING agent-as-tool pipeline end-to-end — no bespoke executor.

- **Server (aidream `services/orchestras/`)** — `read_orchestra()` resolves the Orchestra from `platform.associations` (marker + ordered members) via the ORM under `acting_as_user(ctx)`; `build_conductor_member_specs(agent_id, ctx)` returns one `AgentToolSpec` per member (description = `role_title — gap`), or `[]` for a normal agent / empty Orchestra. **Modes are real (D-36, 2026-08-15):** `sequential`/`parallel`/`dag` (written by the "How members run" picker in `OrchestraSettingsDialog` → `OrchestraConfig.mode`) run as a compiled deterministic plan on the server instead of member-as-tool projection; an unknown mode fails LOUDLY server-side — never a silent memberless run. `prepare_agent_run` (`ai_execution/agent_run.py`) calls it right before `apply_unified_tools` and concatenates the specs onto `request.tools`. From there it's the standard `agent_projection.resolve_agent_specs` → `executor.py` `ToolType.AGENT` → nested child run → `inline` result path, with the existing recursion guard + cost spine. See `aidream/services/orchestras/FEATURE.md`.
- **The conductor must be a tool-CALLING supervisor**, not a planner that only emits a JSON dispatch plan and never delegates. **That is now what the TEMPLATE says** — `agent.template` `b06689e3` was rewritten in the live DB on 2026-08-16 to the supervisor prompt (with the `<available_agents>` marker intact so **Sync agent listings** still fills it, and a `{{task}}` / `{{additional_context}}` user message). A fresh copy is therefore correct at birth and `useCreateConductor` only renames it.

  🚨 **Never reintroduce a code-side prompt override.** Until that date the flow overwrote every generated agent's messages with `CONDUCTOR_SUPERVISOR_PROMPT` + `CONDUCTOR_USER_TEMPLATE` from `conductor/constants.ts`, because the template still carried the obsolete planner prompt. That made this repo the real definition of every conductor in the product and reduced the template row to decoration — a user editing it saw no effect. If conductors need to say something different, **edit the template**.
- **FE — Run.** On desktop, the builder header's **Run** action opens an **embedded run panel** (`orchestras/run/OrchestraRunPanel`) beside the canvas — the canonical `AgentRunnerPage` under surfaceKey `orchestra-builder:${conductorId}` (`sourceFeature: "agent-runner"`, `retainOnUnmount` so closing the panel never kills a stream), with an "open full runner ↗" affordance. Mobile (and `OrchestraCard`) keeps the full-route `/agents/:id/run` — canvas highlight is meaningless on a phone. The run panel and the member/conductor inspectors are mutually exclusive (one right-side panel).
- **Live member highlight (BUILT — mount model: embedded run panel).** When the conductor runs, member nodes light up live on the REAL canvas. The chain: each member executes as a `sub_agent` operation whose stream `init` carries `metadata: {label: "custom_tool_N", conversation_id: <child uuid>}` (the member's agent_id is deliberately opaque on the wire — matrx_ai agent projection). `trackOperationInit` now persists that metadata on the operation entry (completion copies it forward). `orchestras/run/` derives status: `orchestra-run-status.selectors.ts` aggregates the run conversation's **latest request's** `sub_agent` ops (statuses reset naturally on a new turn); `useOrchestraMemberRunStatus` resolves each child `conversation_id → initial_agent_id` via one cached `chat.conversation` select (module-level cache + in-flight dedupe, never polled; non-member children filter out via the memberIds set). The run conversation is observed canonically from the **conversation-focus registry** (`selectDisplayConversation("orchestra-builder:${id}")`) — no runner fork. Status reaches nodes via `OrchestraRunStatusContext` — **never through node `data`** (that would churn the canvas's `sig`-keyed reconcile). Visuals: running = animated accent pulse + spinner badge; done = emerald ring; failed = destructive ring; Grid rows show the same state as a small dot.
- **How each member's result comes back (D-40, 2026-08-16)** — the member edge's `metadata.result_mode` (`inline` default | `reference` | `inline_once`), written by the **"When this member answers"** picker in `MemberInspector`, beside "Must be consulted". `reference` is the Orchestra's advertised power made real: the member's answer goes to the conversation value store and the conductor holds only a short descriptor with a ```matrx fence it can hand to another member — its context never carries the content. The server projects `value_store` alongside the members whenever any of them is non-inline, strict-parses the value (an unrecognized one fails the run loudly, never a silent fall back to inline), and re-applies it on every continuation and on the mid-run roster refresh. Written only when it is NOT the default, so an all-inline roster's edges are byte-identical to before. Live-proven: `aidream/scripts/_verify_orchestra_result_mode.py`.
- **Multi-turn:** the projection re-runs on EVERY turn (both the new-conversation and continue paths) — the persisted config keeps only the member tool *names*, not their agent-projection definitions, so turn 2+ must re-inject or members drop out.
- **Deployed, not yet verified:** the aidream half shipped in commits `153ad4291` + `ce852fcaa` (2026-07-15) and has been live since that day's release — but no end-to-end delegation run has been confirmed. Smoke-test with the AI Dream MCP `agent_run` tool on an conductor (send a 2nd message to confirm members persist).

## Invariants

- **No `orchestra` table, ever.** Membership is association edges. New write → reuse `associationsService`, never a bespoke RPC.
- **React Flow (`@xyflow/react`) lives ONLY in `OrchestraBuilderCanvasImpl.tsx`**, reached via the `OrchestraBuilderCanvas` `next/dynamic({ ssr:false })` wrapper. A static import anywhere else is a build-time leak — guarded by `reactFlowStaticImportBan` in `eslint.config.mjs`. See the `code-splitting` skill.
- **`agent` is a curated `ASSOCIATION_TARGET_TYPES` member** (`features/scopes/types.ts`) so agent→agent is a permitted edge.
- **Runtime delegation (P0+P1) is BUILT** (member-as-tool supervisor) — see the section below. Pipelines/DAG (Phase 2+) are still designed-for via `role`/`metadata`, not built. The full prioritized path is in [`ORCHESTRAS_ROADMAP.md`](./ORCHESTRAS_ROADMAP.md).
- **The library rail reuses the canonical agent filter** (`useAgentConsumer` + `makeSelectFilteredOwned/SharedAgents` + `<DesktopFilterPanel>`), never a bespoke list. Peek is **non-blocking**: `AgentPeekButton` opens `AgentSneakPeekContent` in a draggable `WindowPanel` (`AgentPeekWindow`, `dynamic()`-imported so `WindowPanel` stays behind the lazy boundary) — never a blocking modal. The inspector lazy-loads the full definition (`fetchFullAgent`) to show inputs + output type.
- **The canvas uses React Flow's own `useNodesState`** (a drag mutates only the dragged node — never re-derive the whole node list from a position-override map, which re-renders every node per drag tick); external changes reconcile via a `sig`-keyed effect. Click/drag bumps a monotonic `zIndex` so the active/expanded node rises above the rest. Controls are themed for dark mode in `orchestra-builder-canvas.css`.
