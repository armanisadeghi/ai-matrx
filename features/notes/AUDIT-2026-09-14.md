# Notes — defect and gap register (audit, 2026-09-14)

Read-only audit of `features/notes/**` and its consumers. Scope: everything that would make a
non-technical high-school student stop trusting Notes, EXCEPT the four failures fixed today.

**The four fixed items were verified present and are not re-reported:**
(a) list read waits for the session — `redux/thunks.ts:225` (`awaitCurrentNotesUser`), error + **Try again** at
`components/NoteSidebar.tsx:1243`; (b) `hooks/useNewNoteOrganization.ts` wired at `NoteSidebar.tsx:190`,
`NoteTabBar.tsx:51`, `FolderQuickPick.tsx:50`; (c) rebase/edited-field CAS at `service/notesService.ts:535-539`
+ `utils/saveVerification.ts:28`; (d) `isDraftAlreadySaved` at `components/NoteDraftRecoveryBanner.tsx:65`.
**All four were fixed on the DESKTOP surface only.** N-01, N-02 and N-05 below are the same three bugs,
still live, on the mobile surface — which is the surface the reported user was on.

Tests: `pnpm jest features/notes --no-coverage` → 37 suites / 234 tests green today.

Severity: **S1** data loss · **S2** lying screen · **S3** confusing error · **S4** friction · **S5** nit.

---

## S1 — Data loss

### N-01 · The mobile note editor has no durable copy of anything the user types
**Defect.** `MobileNoteEditor` keeps the note body in React state and only reaches Redux/the DB inside a 2s
timer that its own unmount cleanup cancels, so text typed and then left within 2 seconds exists nowhere.

**Sequence.** Open a note on a phone → type a sentence → tap Back (or another note, or the OS back gesture)
within 2 seconds → the text is gone, silently, and is not in the draft store either.

**Evidence.**
- `components/mobile/MobileNoteEditor.tsx:77` — body lives in `useState`, never dispatched as the user types.
- `:172-202` — a 2000 ms `setTimeout` is the *only* path to `updateNote`.
- `:213-218` — the effect cleanup `clearTimeout`s that timer with **no flush**. Desktop does the opposite:
  `components/NoteContentEditor.tsx:423-437` flushes the pending buffer to Redux on unmount.
- `:123-136` — a `note.id` change resets `localContent` from the (stale) note prop; a mid-debounce note switch
  discards the edit.
- Local drafts are inert here: `utils/notesDrafts.ts:53-58` needs either `record._dirty` (Redux, which mobile
  only writes at save time via `hooks/useNotesRedux.ts:160-175`) or `getNoteLiveContent` (mobile never calls
  `setNoteLiveContent` — confirmed, zero hits under `components/mobile/`).

**Test?** No. `components/mobile/MobileNoteEditor.transition.test.tsx` covers tag preservation only; no test
lets that timer fire or unmounts mid-debounce.

**Fix.** Make the mobile editor write through the same path as desktop: `setNoteLiveContent` + a debounced
`updateNoteContent` dispatch on change, and let `autoSaveMiddleware` own persistence — deleting the bespoke
2s timer entirely.

**Layer.** `features/notes` (mobile editor); the primitive it should join already exists in the feature.

### N-02 · Signing out or switching accounts destroys unsaved text with no capture and no warning
**Defect.** `resetNotesState()` returns the whole slice to `initialState`, dirty records included, and no
caller snapshots the drafts first — even though the function to do it exists and is documented for exactly
this ("call before anything that discards the editor's buffer", `utils/notesDrafts.ts:84`).

**Sequence.** Type into a note → sign out (or the session flips to another account) → text gone, no draft, no
sentence. On a shared school machine this is the normal exit.

**Evidence.** `redux/slice.ts:1671-1673`; called at `components/NotesView.tsx:277` and `:285`, and
`hooks/useNotesRedux.ts:94`. `captureNoteDrafts` has exactly **one** production caller —
`utils/writeErrors.ts:92` (after save failures). Nothing else captures.

**Test?** No.

**Fix.** Call `captureNoteDrafts("account-change")` immediately before every `resetNotesState()` dispatch, and
have `useSignOut` capture before it clears the session.

**Layer.** `features/notes` for the calls; the sign-out ordering belongs in `features/shell/auth/useSignOut.ts`.

### N-03 · Drafts are captured on `pagehide` only, which is the event mobile browsers skip
**Defect.** The only automatic snapshot trigger is `pagehide`. A backgrounded tab that the OS evicts — the
normal way a phone or Chromebook ends a session — fires `visibilitychange` and often never fires `pagehide`,
so up to one full debounce window of typing (3s, 5s or **10s**, `redux/notes.types.ts:409-413`) plus the
200-1000 ms editor buffer (`:425-429`) is lost with nothing recoverable.

**Evidence.** `node_modules/@ai-matrx/kit/dist/drafts.js:96-101` — `attachUnloadListener` registers `pagehide`
and nothing else. `components/NotesView.tsx:298-314` already listens to `visibilitychange`, but only to
*refetch*; it never captures.

**Test?** No.

**Fix.** Capture on `visibilitychange → hidden` as well as `pagehide` (idempotent, cheap), in the drafts
package so every feature inherits it.

**Layer.** Shared — `@ai-matrx/kit/drafts` (`aidream/apps/shared/kit`). Same-session law applies.

### N-04 · Restoring a version does nothing to the open note, then the editor writes the old text back
**Defect.** Every restore callback dispatches `fetchNoteContent`, which **returns early for any note that is
already loaded** — which an open note always is. The DB really restores; the editor never learns.

**Sequence.** Open a note → Version History → Restore v3 → toast says "Restored to v3" → the editor still shows
the current text with a stale base → the next autosave overwrites the restore, or the user gets a Note
Conflict dialog about their own note.

**Evidence.** `redux/thunks.ts:338-340` (`if (existing?._fetchStatus === "full") return null;`) against the
four callers: `components/NotesView.tsx:857`, `components/NoteHistoryPane.tsx:68`,
`components/NotesWindowView.tsx:157`, `features/agents/components/context-items/bodies/NoteBody.tsx:123`.
`refreshNoteContent` (`thunks.ts:385`) is the thunk that bypasses the guard, and no restore path calls it.

**Test?** No — `components/NoteVersionHistory.tsx` and `components/diff/NoteVersionHistoryPanel.tsx` have zero
test references.

**Fix.** Restore callbacks dispatch `refreshNoteContent`; and because a restore intentionally replaces the
buffer, capture a draft first and clear the note's dirty/base state as part of the restore, not after it.

**Layer.** `features/notes` (one shared `onVersionRestored` handler, not four call sites).

### N-05 · A failed save never retries itself; coming back online changes nothing
**Defect.** There is no offline awareness anywhere in Notes (`navigator.onLine` / an `online` listener: zero
hits under `features/notes/`), and the autosave middleware only re-fires on the **next edit**
(`redux/autoSaveMiddleware.ts:52-62` — it is action-triggered). Mobile additionally parks itself after one
failure (`components/mobile/MobileNoteEditor.tsx:175,198`).

**Sequence.** School wifi drops → saves fail → the student stops typing (class ends) → wifi returns → nothing
ever retries. Desktop at least escalates to the blocking banner after 3 failures
(`components/NoteSaveFailureBanner.tsx`, threshold `redux/notes.types.ts:423`). **Mobile has no banner at all**
— one toast, then silence (grep: `NoteSaveFailureBanner`, `NoteDraftRecoveryBanner` and `NoteConflictWindow`
are referenced only from `components/NoteContentEditor.tsx:1091,1093,984`).

**Test?** Partly — `redux/saveFailureEscalation.test.ts` covers the desktop escalation. No test for reconnect
retry (there is nothing to test) and none for the mobile failure surface.

**Fix.** One `online`-event + backoff retry for every dirty note, in the middleware; and render the existing
`NoteSaveFailureBanner` + `NoteDraftRecoveryBanner` in `MobileNoteEditor`.

**Layer.** `features/notes`; the retry policy is a candidate for `lib/sync/engine/autoSaveScheduler.ts`, which
already implements exactly this contract and which Notes does not use (see N-12).

### N-06 · A folder move that fails to save still shows the note in the new folder
**Defect.** `moveNoteToFolder` writes `folder_name` and `folder_id` into Redux optimistically and then awaits
`saveNote`. If the save rejects (RLS, conflict, offline) nothing rolls the fields back — the sidebar shows the
note in the new folder until a reload puts it back in the old one.

**Evidence.** `redux/thunks.ts:1356-1372`.

**Test?** No — `moveNoteToFolder` and `moveNoteToNewFolder` have no test.

**Fix.** Roll the two fields back in the rejection path and say the move did not happen; or move through the
canonical save receipt and apply the fields only on `applied`.

**Layer.** `features/notes`.

---

### N-07 · The same note can be opened in both split panes, where the two editors fight over one buffer
**Defect.** `SplitNotePicker` refuses the currently-active note (`components/SplitNotePicker.tsx:45,51`), but
nothing stops the user from then switching the **main** tab to the note already in the split pane —
`setInstanceActiveTab` has no split check (`redux/slice.ts:1241-1253`) and `setSplitNote` has none either
(`:1323-1329`). Two `NoteContentEditor` instances then share one global live-content map keyed by note id
(`utils/noteLiveContent.ts:6`), and each pane's unmount runs `setNoteLiveContent(noteId, null)`
(`components/NoteContentEditor.tsx:426`), wiping the other pane's rescue buffer; concurrent typing in both
panes resolves last-debounce-wins over the whole body.

**Test?** No.

**Fix.** Refuse the collision at the reducer: activating a tab that equals `splitNoteId` clears the split (or
swaps the panes), so one note is never mounted twice.

**Layer.** `features/notes`.

## S2 — Screens that lie

### N-08 · On mobile, a notes list that failed to load says "No notes yet — tap + to create one"
**Defect.** This is Ava's screen, and it is still live. `MobileNotesList` never reads list status or list
error — it renders the empty state whenever the array is empty, including when the read errored.

**Evidence.** `components/mobile/MobileNotesList.tsx:276-283`; no reference to `selectNotesListStatus` /
`selectNotesListError` anywhere in the file, versus the desktop error + **Try again**
at `components/NoteSidebar.tsx:1243`. Mounted at `components/NotesView.tsx:742`.

**Test?** No.

**Fix.** Give `MobileNotesList` the three honest states the sidebar now has (loading / error + Try again /
genuinely empty), reading the same two selectors.

**Layer.** `features/notes`.

### N-09 · Past 1000 notes the list silently truncates and every derived screen is wrong
**Defect.** The list read is a bare `.select()` with no `readAllRows` and no pagination, so PostgREST caps it
at 1000 rows without an error. Folder derivation, "all notes", search and the sidebar all treat that
truncated array as complete.

**Evidence.** `redux/thunks.ts:228-238` (list) and `:1496-1504` (trash) — zero `readAllRows` / `.range(` /
`.limit(` in `redux/thunks.ts`, `service/notesService.ts`, `service/notesApi.ts`. The rule is stated in
`CLAUDE.md` ("a list you treat as complete is read with `readAllRows`"); sweep: `pnpm check:unbounded-reads`.

**Test?** No.

**Fix.** `readAllRows` from `@ai-matrx/data/db` for both reads.

**Layer.** `features/notes` (the primitive already exists).

### N-10 · Every note in the list is stamped as created by the current user, even when it is not
**Defect.** Both list reads set `created_by: userId` on every row, but the query is only filtered to
`created_by` when `scopeToOwner("note")` returns true. Under organization scope the rows include other
members' notes and are then labelled as mine.

**Evidence.** `redux/thunks.ts:236` + `:261` (list), `:1503` + `:1512` (trash); `lib/list-scope/index.ts:154`
returns false whenever the registry word for `note` is `organization`. Consequence: the note information
panel names the wrong author, and `deleteNote`'s share gate (`thunks.ts:1168-1174`) only guards
`_sharedWithMe` records — an org row that looks self-created walks past it into the soft-delete.

**Test?** No.

**Fix.** Keep the row's real `created_by` (add it to the select list) and stop stamping.

**Layer.** `features/notes`.

### N-11 · Refresh silently does nothing on the note you are editing, and swallows every failure
**Defect.** `refreshNoteContent` returns `null` for any dirty note (correctly, to protect the buffer) but says
nothing; and `handleRefresh` wraps everything in `Promise.allSettled` with no result inspection, so a refresh
that failed outright looks identical to one that worked.

**Evidence.** `redux/thunks.ts:392-394`; `components/NotesView.tsx:406-425`.

**Test?** No.

**Fix.** Report what the refresh skipped and why ("your unsaved edits are still here, so this note was left
alone") and surface a failed refresh instead of settling it away.

**Layer.** `features/notes`.

---

### N-12 · Notes runs a bespoke autosave timer instead of the platform scheduler that solves this
**Defect.** `lib/sync/engine/autoSaveScheduler.ts` already implements per-record debounce, identity-swap
cancellation, `AbortSignal`, `flushAll()` and a `pagehide` flush. `autoSaveMiddleware` is a hand-rolled
`Map<string, Timeout>` with none of it — no flush, no abort, no reconnect.

**Evidence.** `redux/autoSaveMiddleware.ts:45,87-140` vs `lib/sync/engine/autoSaveScheduler.ts:61,331-373`.
N-01, N-03 and N-05 are all downstream of this choice.

**Test?** The middleware's own timer never fires in any test (no test references `getAutoSaveDelay`,
`generateLabelFromContent` or `notesAutoLabel`).

**Fix.** Adopt the scheduler, or at minimum give the middleware its `flushAll`/abort surface and call it from
the same places the scheduler does.

**Layer.** Shared — `lib/sync/engine/`.

### N-13 · A folder disappears the moment its last note leaves it
**Defect.** The folder list is derived purely from the folders currently referenced by loaded notes; there is
no read of `note_folders` for display. Move or trash a folder's last note and the folder vanishes from the
sidebar and from every picker, while its row still exists server-side.

**Evidence.** `redux/selectors.ts:73-103` (`selectAllFolders`, `selectFolderReferences`),
`utils/noteUtils.ts:41-43`; the table is only read for admission (`redux/thunks.ts:1343-1350`) and creation
(`service/notesService.ts:833-849`). Only the six defaults survive empty
(`constants/defaultFolders.ts:19-24`).

**Test?** No.

**Fix.** Read the folder list from `note_folders` for the organization and union it with the derived names.

**Layer.** `features/notes`.

---

### N-14 · A note from another organization is loaded, hidden, and cannot be moved out of hiding
**Defect.** The fetch has no organization predicate, so notes from every organization the user can read land
in Redux; the sidebar then hides the ones outside the active org purely client-side. The note stays reachable
by id (restored tab, deep link, global search) but appears in no folder, and the folder picker is built from
the active org, so `moveNoteToFolder` refuses it by design.

**Evidence.** fetch with no org filter `redux/thunks.ts:229-238`; client-side hide
`utils/noteUtils.ts:20-31`, applied at `components/NoteSidebar.tsx:224` and
`components/mobile/MobileNotesList.tsx:93-96`; refusal `redux/thunks.ts:1335-1338,1352-1354`.

**Test?** No.

**Fix.** Either filter at the query (the note then simply is not there) or show it with its organization named
and a "switch organization to work on this" door. The current middle state is a dead end.

**Layer.** `features/notes`; the rule about active-org and access belongs in
`docs/official/db-rules.md` §6 ("access never depends on the active org").

## S3 — Errors that speak jargon

### N-15 · A database key name is shown to the user as an error message
`service/notesService.ts:892` — `"notes_folder_cross_org_legacy_key: this folder name is reserved in another
organization until the folder-key cutover is activated."` reaches a toast through
`components/NotesLayout.tsx`'s `toast.error(error)`. Rewrite: *"That folder name is already used in another
workspace — pick a different name."* **Test?** No. **Layer:** `features/notes`.

### N-16 · Save/prepare errors use terms no user can decode
Each of these can reach a toast: `"This draft still names a folder that has not been admitted in this
organization…"` (`service/notesService.ts:179`), `"This note editor has no valid acknowledged base. Reload it
before saving."` (`features/rich-document/actions/sources/note.ts:35`), `"A note must be prepared with its
acknowledged full row before saving."` (`:59`), `"The note was saved, but one or more context links could not
be saved."` (`service/noteSaveErrors.ts:40`). "admitted", "acknowledged base", "full row", "context links" are
all internal words. **Fix:** one translation table at the toast boundary — the thrown error keeps its
diagnostic text for capture, the user gets a sentence. **Layer:** `features/notes`, using
`utils/writeErrors.ts` as the single seam.

### N-17 · A raw database message is concatenated into the user's toast
`service/notesService.ts:215` — `` `This new note was not confirmed as saved… ${error.message}` `` and
`components/NoteEditor.tsx:174` — `` `Failed to save note: ${err.message}` ``. Both append unbounded provider
text. **Fix:** never concatenate; capture the detail, show the sentence.

### N-18 · Restore failure says nothing and captures nothing
`components/diff/NoteVersionHistoryPanel.tsx:165-166` — `catch { toast.error("Failed to restore version"); }`
discards the error entirely: no `captureError`, no reason, no retry. Violates "nothing fails silently".

## S4 — Friction

### N-19 · Mobile "+ New Note" fails completely silently when the organization has not resolved
This is bug (b) from today, unfixed on mobile: `components/mobile/MobileNotesList.tsx:152-160` calls
`findOrCreateEmptyNote`, whose `requireOrganizationContext` (`redux/thunks.ts:1289`) throws
`OrganizationContextError`, and the catch is `console.error` only. The tap does nothing, forever, with no
message. No mobile file references `useNewNoteOrganization` or `useDraftInitializationControl`. **Fix:** use
the same hook and render `OrganizationRequiredNotice`. **Layer:** `features/notes`.

### N-20 · Mobile has no version history, no find-and-replace, and no conflict surface at all
`NoteVersionHistory`, `FindReplaceBar` and `NoteConflictWindow` have zero references under
`components/mobile/`. The conflict gap is the serious one: mobile writes through
`hooks/useNotesRedux.ts:160-175` → `saveNote`, so a CAS conflict *is* recorded, and mobile renders nothing for
it — the save simply keeps failing. **Layer:** `features/notes`.

### N-21 · Deleting a note discards unsaved edits without saying so
`redux/thunks.ts:1150-1201` removes the record while a debounce may still be pending; the timer then finds no
record and returns (`redux/autoSaveMiddleware.ts:92-94`). Undo restores the server's older text with no
mention that newer typing went with it. **Fix:** capture a draft before `removeNote` and name it in the undo
toast. **Test?** No — `deleteNote` and `hooks/useNoteDelete.ts` have no test (the hook is mocked away in
`components/mobile/MobileNoteEditor.transition.test.tsx:16`).

### N-22 · Trash hydration re-introduces the per-item dispatch loop the freeze doctrine bans
`redux/thunks.ts:1509-1516` dispatches one `upsertNoteFromServer` per deleted note, re-running every sorted
list selector per row — the exact O(N²·log N) shape the list read was fixed for
(`redux/thunks.ts:253-265`). **Fix:** one `upsertNotesFromServer` batch.

### N-23 · Every keystroke re-sorts the entire notes collection
`selectAllNotesList` (`redux/selectors.ts:58-71`) and `selectAllFolders` (`:73-90`) recompute on any change to
the notes map, and `updateNoteContent` changes it on every Redux sync (200-1000 ms). At a few thousand notes
that is a full filter+sort+folder-set rebuild several times a second while typing. **Fix:** key the sort off a
list-revision counter that content edits do not bump, or sort ids and look rows up lazily.

### N-24 · The list read pulls the full body of every note on every route entry and every refresh
`redux/thunks.ts:233` selects `content` for the whole list, and `handleRefresh` re-runs it
(`components/NotesView.tsx:410`). **Fix:** drop `content` from the list projection; `fetchNoteContent` already
fetches bodies on demand.

### N-25 · An agent can replace the entire note body through one write target
`components/NoteContentEditor.tsx:650-656` — `note_content` calls `handleChangeFlush(value)`, replacing the
whole document. Recovery is the generic undo plus the `RecentChangeOverlay` flash. Given the
destructive-and-expensive-actions law, verify that the surface-write approval layer shows the user what will
be replaced before it lands; if it does not, this is an S1. **Flagged for verification, not asserted.**
