## The contract — the stored text is the truth

- **No edit → the stored bytes.** Open, switch Visual/Source/Preview, save: byte-identical (`serializeVisualDocument` writes every unchanged block as its stored bytes).
- **An edit changes bytes only where the person typed.** Only changed blocks are serialized (`core/markdown-serialize.ts`) in the author's own spelling (`md*` attrs: `*`/`-`, `**`/`__`, `1)`, heading style, quote prefix, link tail, table row bytes). **No escapes are ever added** (a literal `|` typed into a table cell is the one exception — it would split the cell).
- **The fidelity gate.** A construct is editable rich text only if the serializer reproduces its stored bytes exactly at load (`core/markdown-parse.ts`); otherwise it is a `sourceLocked` atom — rendered, edited as source, written back verbatim.
- **A ```matrx fence is a chip or a card, never code** (2026-10-02): one island, drawn by the shared renderer, no JSON on screen; its bytes never change.
- **Host inserts parse like a paste.** `RichEditorController.replaceSelection` / `insertText` (the right-click menu, AI Replace / Insert below, dictation) go through `replaceSelectionWithMarkdown` — never literal characters.
- **Islands are bytes.** Kinds / `__kind` JSON, XML sections, fences, math, HTML, comments, anchors, `{{vars}}`, citations, tags are atoms (`islandBlock`, `inlineIsland`) edited only in their own editor (`islands/IslandCodeEditor.tsx`, `replaceIslandRaw`). Typing over a selected island starts a paragraph after it.
- **Moves and pastes rewrite nothing they did not bring.** A block move (⌘⇧↑/↓, the grip menu, a grip drag) changes only the order: every other block stays its baseline node and is written back as its stored bytes. There are **no Tiptap paste rules** in the schema (`createRichEditorExtensions` strips `addPasteRules` from every extension): Tiptap runs them over the whole changed range of a paste or a DROP, and a drag's range spans every block it passed, so the link rule once re-marked an untouched bare `ops@example.com` into `[ops@example.com](mailto:…)`. Plain-text paste (a text editor, a terminal, ⌘⇧V) is parsed by the ONE parse path (`core/paste-markdown.ts` → `buildVisualDocument`), source identity stripped — a pasted list is a list, a pasted `<section>` one island, a `{{var}}` a chip. HTML paste goes through the schema's HTML rules (`html-to-markdown.ts`).
- **Callouts, directives, footnote definitions and wikilinks are islands** (content-ir 0.14): stored ones change only through their island editor; `setCallout` on new prose writes a fresh `> [!TYPE]`.
- **Author escapes read as the character.** `\*`, `\_`, `\|`… load as the bare character under the non-inclusive `mdEscape` mark; the serializer writes the backslash back before each ASCII punctuation character in it. Text typed beside it is plain — the editor never adds an escape.
- **Undo is the person's own act** (`core/history-approval.ts`): the island bytes an undo/redo takes away (Visual: prosemirror-history meta; Source: CodeMirror `undo`/`redo` user events) are approved, so reversing an island edit — even across a save — never asks for consent.
- **Tables — THE writer is `core/table-source.ts`.** `rewriteTableSource(original, grid)` is the one way any edit path writes a table back (the rich editor's serializer AND the in-body answer table editors MarkdownTable / TableWithSeparatedControls / StreamingTableRenderer): an untouched cell is its source bytes (padding, escapes, `\|`), only an edited cell changes, a row added/removed changes only its line. The ONE parser (`parseMarkdownTable`) reads `\|` as part of a cell. Guard `pnpm check:table-writers` (shrink-only). A re-aligned column rewrites only its own delimiter cell (same width, same spaces); a column added or removed rewrites the delimiter row.
- **The save gate (`core/save-plan.ts`).** Every view saves through `planSave(stored, current)`: block-LCS regions, island accounting (removed / changed / swallowed need consent unless changed through the island's own editor; moved never asks), then content-ir 0.13's strict splice in two proven steps — `islandEdit` for island changes, block edits for prose. Validation offers, never blocks: the consent dialog always has **Save anyway**.

## Edit in place — THE primitive for editable rendered rich content (2026-10-05)

Wherever rich content is rendered AND the person may edit it, the host wraps the render in `in-place/EditInPlace.tsx` (`value`, `canEdit`, `write`, optional controlled `editing` for the host's own Edit button). A double-click on the text (never on a link, button or field) swaps the render for THIS editor in the same place, never shorter than the render was; the caret lands where they clicked (`core/caret-context.ts` — the click travels as the rendered text around it, found again by `RichEditorController.placeCaret`). Esc/Cancel leaves (a changed draft asks first; Esc belongs to the innermost open menu/island/find first), ⌘/Ctrl+Enter saves, formatting and copy come with the editor. The editing half is `in-place/InPlaceEditor.tsx` (also used directly by the AI answer; `actions` adds outcomes beside Save — a chat message's Save & resubmit / Fork & resubmit; `expandable` = the same instance full screen). **Bytes:** `in-place/in-place-session.ts` — explicit hosts write only changed text on Save, never on cancel; autosave hosts (`mode="autosave"`, notes) write only drafts that differ from the last written text, and a discard after edits puts the opened bytes back once. Hosts: AI answer (+ double-click via `useInPlaceTrigger` + `caret-handoff.ts`), your own chat message, notes Read (desktop + phone, autosave; the note's mode never changes), study guides you own, the markdown studio preview, task descriptions, transcription cleanup output. Guards: `__tests__/edit-in-place-hosts.census.test.ts` (a rendered rich host with an edit path and no edit in place fails; self-proof plants one), `in-place/__tests__/in-place-bytes.test.ts` (per host; red first against a naive session), `__tests__/caret-context.test.ts`.
