## Stack

Next.js 16.2+ (App Router) · React 19.2 · TypeScript 6.0+ (strict, no `any`) · Tailwind 4.3+ (CSS-first, `@theme`) · Turbopack · pnpm 10.29+ · Redux RTK · Supabase · Stripe · Vercel. State minimums, never exact patches — `next`/`react`/`typescript` are declared `latest` and drift on every install. Mobile companion: Expo 54 / RN 0.81. Always use the latest stable release of every package — no deprecated APIs. Dependencies come from the npm registry only — never `github:`/`git:`/tarball specs (`pnpm check:registry-deps:strict`); patch by vendoring (see `hooks/usehooks/`).

## Data flow — no Next.js middle tier, Python is not a DB gateway

- **Reads/writes go React → Supabase directly** (RLS + auth-checked `SECURITY DEFINER` RPCs are the authorization layer). Never through Next.js API routes, Server Actions, or the Python server. Exception: admin-only ops gated by a secret token.
- **Compute** (AI, files, heavy work) → Python backend at `https://server.app.matrxserver.com`, called directly — only when the request genuinely needs the server (file bytes, URL signing, heavy processing, an auth/anon boundary). Never for a plain DB read/write.
- **One canonical path per operation.** Two surfaces reaching the same data two ways is a bug — collapse to the direct path.
- **Next.js API routes never sit between React and Python.** Reserve them for true Next-only concerns (secret-token admin RPCs, webhooks, OG images, the agent feedback MCP/REST surface at `app/api/mcp/`).
- **Optimistic concurrency:** guarded read-modify-writes use [`utils/supabase/guardedUpdate.ts`](./utils/supabase/guardedUpdate.ts) — never hand-roll a variant, never compare `updated_at`. Cross-repo SoR: `../common-docs/systems/platform/optimistic-concurrency/FEATURE.md`.

## Migrations — the DB is the source of truth, not the files

A `.sql` file changes nothing until **applied AND verified live AND `pnpm db-types` regenerated**. App code has no DDL path; agents apply DDL via Supabase MCP (`apply_migration`/`execute_sql`). Migrations are idempotent; after applying, upsert the shared ledger `public._schema_migrations` (`source='matrx-frontend'`, checksum = SHA-256). Index hot tables only with `CREATE INDEX CONCURRENTLY`. Verify: `pnpm check:migrations` (unapplied/drift) + confirm live via `execute_sql`. Schema truth vs code: `pnpm check:schema` ([`scripts/schema-check/FEATURE.md`](./scripts/schema-check/FEATURE.md)); drift in an autogenerated file means regenerate the source, never hand-edit. Before canonicalizing tables or acting on conformance counts: `../common-docs/policies/database-changeover-doctrine.md`.

**`pnpm type-check` is the ONLY type gate** — `next.config.js` sets `ignoreBuildErrors: true`, so a green build proves nothing about types. Never a hand-rolled `tsc`; never exclude shipped code from `tsconfig.typecheck.json` to make it pass. Run it before reporting done. **Invoke the `finalize-and-ship` skill** at the end of any task.

## Release — `git push` deploys NOTHING

- Commit as you go, push, don't end a turn with a dirty tree or unpushed commits. Unpushed work doesn't exist; work left local reads as shipped to the next agent.
- **Vercel builds only release-prefixed commits** (`vercel.json` → [`scripts/vercel-ignore-build.sh`](./scripts/vercel-ignore-build.sh)); a plain push to `main` ships to no user, ever — deployments show `CANCELED`, which is normal and not evidence of a problem. **`./scripts/release.sh` / `./ship.sh` is the ONLY way to build**: gates, pending migrations, version bump, prefix. Never disable a check inside it — emergency skips are the per-invocation `--no-migrate` / `--no-gates` flags.
- **One repo, THREE Vercel projects:** `ai-matrx` (aimatrx.com), `ai-matrx-manage` (manage.aimatrx.com → `(admin)`), `ai-matrx-demos` (demos.aimatrx.com → `(dev)`), selected by prefix `release:` / `release-admin:` / `release-demos:` / `release-all:` (`./ship.sh "msg" --target admin|demos|all`). Shared runtime code feeds every profile → automatic releases use `--target all`. `MATRX_PROFILE` env picks the build slice; excluded groups are parked for the process lifetime; **cross-group `app/(x)` imports are banned** — import from `features/`/`components/`.
- 🚨 **Never report deployment status to Arman, and don't run `release.sh` unless he asks for a release right now** — the `Matrx frontend release watch` automation owns the cadence. Say what you built and how you verified it.
- PR/branch sessions auto-merge to `main`; nobody reviews. Half-deployed cross-repo features are the dangerous state — ship both halves. Verify what you can where you are; you are not expected to verify production for a deploy you didn't run.
