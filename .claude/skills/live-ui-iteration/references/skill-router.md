# Live UI skill router

Invoke only the skills whose areas the focused surface actually touches, but never skip a required owner because the user's visible request was small.

## Always

- `browser:control-in-app-browser` — isolated localhost interaction and screenshots
- `surface-check` — S1–S18 driver, fixes, live proof, and ledger
- One UI posture — `ui-refine` for a roughly correct existing page; `ui-sharp` by default for broader redesign; `ui-dense` for all-day power work; `ui-reimagine` only when reinvention is requested
- `ios-mobile-first` — responsive mechanics and mobile proof
- `no-dead-ends` — every named record, count, and detected problem opens or acts
- `context-docs` — FEATURE.md and instruction updates

## Surface and agent context

- `surface-authoring` — new, stub, partial, unregistered, drifted, or incompletely wired agent-aware surfaces; includes the former Surface Pro runtime rollout
- `context-menu-v3` — add, repair, or certify canonical right-click/long-press behavior
- `agent-disclosure` — REQUIRED when a surface already has a fixed AI worker: register it in the existing top Agents menu through a manifest `agentRole` or UI-free `useDeclaredSurfaceMandates`, and use the mandate window instead of a route link. Disclosure NEVER adds visible page content. Agent-AUTHORING surfaces are exempt; universal hosts such as Chat use `agentRosterMode: "universal"` and expose no bound roster or Bind control.
- `surface-write-targets` — agent-writeable fields and live apply proof
- `admin-debug-context` — only when the feature needs custom debug data beyond the automatically captured route/viewport/console context

## Structural UI branches

- `core-route-headers` — any `(core)` route header/body/clearance work
- `overlay-system` — opening, registering, or rendering dialogs, sheets, modals, or windows-as-overlays
- `window-panels` — the WindowPanel primitive, tray, drag/resize, persistence, or mobile presentation
- `compact-nav-menus` — sidebars, navigation lists, compact menus
- `efficient-tap-button-migration` — touch targets or legacy button controls

## Conditional correctness owners

- `type-safety` before fixing a type error or changing Supabase query/RPC typing
- `supabase-realtime` before changing any channel, echo, autosave, or realtime loop
- `code-splitting` before any dynamic import or chunk-entry change
- `light-dark-integrity` for theme violations
- `real-loading-states` for loading, empty, error, or fallback UI
- `no-emojis-in-ui` for any user-visible emoji encountered in touched files
- `agent-review-queue` to read exact-route feedback and manage existing rows; do not create a new row when Arman reviewed the work live
- `finalize-and-ship` only at actual task completion, following the repository's higher-priority release rule: never run a release unless Arman explicitly asks for one now
