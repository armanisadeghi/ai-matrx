### Criteria

- **C1** The tile renders the canonical component with every control the page has, never a preview or look-alike.
- **C2** Full surface: the manifest covers every read and every action the page offers. Document body text,
  which people edit on the page, is part of the task, not a deferred follow-up.
- **C3** A page-level surface is extracted into ONE shared host/component used by the page and the tile.
- **C4** Declares `briefValues`.
- **C5** Proof has an agent reaching the item while a DIFFERENT tile is live
  (`board_items` → `board_open_item` → `board_item_act`), plus exactly one registration while selected.
- **C6** No board-specific agent tools.
- **C7** `startNew` / `bringIn` / `href` correct: the record is created through the canonical create path with
  the organization gate, and never in a mount effect.

Facts checked against the code (they decide C2, C3 and C7):
- `app/(core)/documents/[id]/page.tsx` mounts `SurfaceRuntimeProvider` at page level (line 235) around the
  inline header and `DocumentEditor`. Extraction is required (C3).
- `features/surfaces/manifests/documents.manifest.ts` declares no body value, write target or client tool
  ("DELIBERATELY NOT DECLARED: the document's body text…", line 31; readiness note line 480), while the page
  lets a person edit the body. The gap is real and inside the task (C2).
- `features/spatial/items/NoteItemBody.tsx`: the mount effect's `start-draft` step starts a client-only draft
  (`initializeAutogeneratedNote`); a row is written on first input or from a seed. Citing that `preparing` ref
  guard to justify creating a Document row on mount misreads the precedent (C7).
